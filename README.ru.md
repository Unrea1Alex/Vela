# Vela 0.7 — библиотека, тесты, FFI и интеграция с агентами

[English](README.md) · [Лицензия MIT](LICENSE)

Версия 0.7.0 добавляет Float64, модули стандартной библиотеки для JSON,
UTF-8, файлов и процессов, именованные тесты и синхронный Windows x64 FFI ABI 1.
Модули imports/pub, локальные проекты с lock-файлами и нативный CLI сохраняются.
Начало работы: [проекты](docs/PROJECTS.md), [краткое руководство агента](docs/AGENT-QUICKSTART.md).
Отдельная необязательная [MCP-поставка](integrations/mcp/README.md) предоставляет
справку, check, format и symbols, включая проверку несохранённого текста.
При настроенной и проверенной Windows LPAC-песочнице доступны build/test/run.
Текущее состояние приёмки — в [плане](docs/ROADMAP.md).
Компилятор, bootstrap и native verify не зависят от Python, Node.js или MCP.
Справка рабочего дерева уточнена после MeasureLab; архивы 0.7.0 сохраняют
документацию момента выпуска. Математика, точность форматирования, JSON-извлечение,
text builder, большие текстовые ресурсы и выдача файлов MCP пока запланированы
в 0.8.7–0.8.10/0.9.7–0.9.9 и не являются доступными API 0.7.0.

Vela компилирует программы в самостоятельные нативные executable через C11.
Компилятор, сборщик исходников, самосборка и тестовый стенд написаны на Vela.
Команды ниже выполняются из корня клонированного репозитория.
Проверенные инструменты Windows x64 включены в `bin`; для сборки из исходников
без готового Vela executable используйте [C recovery seed](bootstrap/README.md).

## Быстрый старт

Из корня проекта в PowerShell:

~~~powershell
.\velac.cmd --version
.\velac.cmd fmt examples/collections.vela --check
.\velac.cmd run examples/collections.vela
.\velac.cmd build examples/factorial.vela -o bin/my-factorial.exe
.\bin\my-factorial.exe 10
.\vela-dev.cmd verify
~~~

Для сборки нужен C11-компилятор. Обёртки автоматически настраивают MSVC x64.
`check`, `symbols`, `emit-c` и готовые программы работают без C-компилятора.
Python в этих командах не используется.

Небольшое готовое приложение: [TimeLog](apps/timelog/README.md) читает TSV-журнал
времени и создаёт автономный HTML-отчёт. [Разбор прикладной проверки](docs/TIMELOG-REVIEW.md)
содержит найденную ошибку форматтера и предложения для стандартной библиотеки.
Приложение версии 0.7: [MeasureLab](apps/measurelab/README.md) читает JSON-измерения,
считает статистику Float64 и создаёт HTML/SVG-отчёт. Его тесты, FFI и MCP-проверка
показывают текущее поведение; [демо-отчёт](apps/measurelab/report.html) использует
синтетические данные, а не замеры производительности компилятора.

## Что появилось в 0.5

- Пользовательские generic-функции, структуры и enum, вывод из аргументов,
  явные ограничения и пределы инстанцирования.
- Option/Result, match-выражения и `?` с выполнением постусловий при раннем возврате.
- For по спискам и диапазонам, break/continue; определённая семантика мутации.
- Интерполяция `f"value={expression:d}"` с явными форматами и исходными позициями ошибок.

Эти конструкции используются в compiler/tools. Пример всех возможностей:
[pipeline.vela](examples/pipeline.vela). Контракты: [GENERICS](docs/contracts/GENERICS.md),
[ERRORS](docs/contracts/ERRORS.md), [CONTROL-FLOW](docs/contracts/CONTROL-FLOW.md),
[FORMATTING](docs/contracts/FORMATTING.md).

## Сохранённые улучшения 0.4

- Отдельные типизированные AST/HIR, таблицы типов и символов с номинальными ID.
- Диагностика ожидаемых/фактических типов, недостающих эффектов и вариантов match;
  связанные объявления и структурированные JSON-поля.
- Нативный `fmt`, `fmt --check` и атомарный `fmt --write`; сохранение комментариев,
  литералов и проверка результата перед записью.
- Защита исходника от перезаписи через алиасы пути, включая Unicode на Windows;
  единый код 2 для отказа C toolchain.

Контракты: [AST/HIR/ID](docs/contracts/AST-HIR-ID.md),
[диагностика](docs/contracts/DIAGNOSTICS.md), [форматтер](docs/contracts/FORMATTER.md).

## Возможности языка, сохранённые из 0.3

- Структуры с именованными полями, конструкторами и доступом через точку.
- Номинальные ID: `type NodeId = distinct Int;`.
- Обобщённые `List<T>` и хеш-словари `Dict<K,V>`, включая вложенные типы.
- Соединение строк через `+` и явное форматирование `to_string(value)`.
- Нативные инструменты разработки и общий каталог `vela/builtins.def`.

~~~text
type NodeId = distinct Int;
struct Node { id: NodeId, name: String }

fn main() -> Unit effects { state, io } {
    let nodes = list_new<Node>();
    list_push(nodes, Node(name: "root", id: NodeId(1)));
    let names = dict_new<NodeId, String>();
    dict_set(names, NodeId(1), list_get(nodes, 0).name);
    print("Node: " + dict_get(names, NodeId(1)));
}
~~~

Структуры копируются по значению. Коллекции имеют общую изменяемую идентичность:
все операции чтения и изменения требуют `state`. Разные номинальные ID
несовместимы; преобразование выполняется явно через конструктор и `.value`.
Подробности и ограничения: [язык](docs/LANGUAGE.md), [память](docs/MEMORY.md).

Сохранены функции, рекурсия, перечисления с данными, исчерпывающий `match`,
контракты, эффекты, проверяемая арифметика, файлы, Unicode пути и аргументы,
старые `IntList` / `StringList`.

## Рабочий цикл

Редактируйте авторские файлы из `selfhost/sources.list`, runtime и каталог.
Не редактируйте генерируемый `selfhost/compiler.vela` вручную.

| Команда | Действие |
|---|---|
| `vela-dev.cmd bundle` | Пересобрать сборщик и автономный исходник |
| `vela-dev.cmd bootstrap` | Три поколения компилятора и проверка сходимости; без тестов |
| `vela-dev.cmd test` | Пересобрать стенд и проверить установленный компилятор |
| `vela-dev.cmd verify` | Самосборка, сходимость, полный стенд; установка после успеха |

Сравнивается C от второго и третьего поколений побайтно. Дополнительно сборщик,
собранный новым компилятором, должен создать тот же автономный исходник.
Логи, поколения и отчёты находятся в `build/native/`; краткие подтверждения —
в `docs/bootstrap-evidence.json` и `docs/test-evidence.json`.

Нативные инструменты: `tools/bundle.vela`, `tools/dev.vela`, `tools/test.vela`.
`.cmd` только настраивает окружение MSVC и запускает executable. Самосборка требует
предыдущий рабочий `bin/velac.exe`. В поставке также есть самостоятельный
C-исходник компилятора для восстановления через C11 без Python.

## Команды компилятора

| Команда | Результат |
|---|---|
| `check SOURCE [--json]` | Проверка языка |
| `symbols SOURCE` | JSON-индекс типов, полей, функций, эффектов и контрактов |
| `fmt SOURCE [--check\|--write]` | Форматирование, проверка стиля или атомарная запись |
| `emit-c SOURCE [-o program.c]` | Самостоятельный C11 со встроенным runtime |
| `build SOURCE -o program.exe` | Сборка с сохранением старого файла при ошибке |
| `run SOURCE -- ARGUMENTS` | Временная сборка и запуск |

## Границы

Контракты проверяются при выполнении. Память динамических объектов принадлежит
процессу и освобождается при его завершении; удаления из коллекций не освобождают
её немедленно. Нет GC, владения, LLVM/WASM, LSP и инкрементальной
компиляции. Generic-тела проверяются при инстанцировании, callable/closure-типы
пока только спроектированы. For по списку создаёт поверхностный snapshot в процессной
области; для обхода без такой копии доступны диапазоны индексов.

Проверенная платформа — Windows x64 / MSVC. POSIX-ветки runtime требуют отдельной
проверки. Сходимость компилятора и тесты не являются формальным доказательством.

Python-код оставлен как историческая реализация языка 0.2. Он читает тот же
каталог встроенных функций, но не поддерживает новые конструкции 0.3–0.7.
`python -m vela` и `vela-python.cmd` — этот старый frontend из репозитория;
для работы используйте `vela.cmd` или совместимый `velac.cmd`.
Старые Python-скрипты bootstrap/verify теперь лишь перенаправляют к нативным
инструментам и не содержат самостоятельной логики сборки.
