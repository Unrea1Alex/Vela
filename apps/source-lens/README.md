# SourceLens · Vela

SourceLens превращает JSON команды `vela query` в автономный HTML-обзор:
модули и импорты, функции, типы результата, объявленные эффекты, места прямых
вызовов и навигация между ними. Поиск и фильтры работают в браузере без сети.
Приложение написано на Vela; небольшой JavaScript внутри отчёта управляет
только фильтрами интерфейса. Анализ выполняет нативный компилятор.

## Контракт приложения

- Вход: полный успешный `vela query ROOT`, schema 1; `--at` с частичным
  результатом не является входным контрактом. Проверяются версия, `ok`,
  документы, связи модулей, положения функций и мест вызова.
- Для большой выдачи можно собрать полный индекс из CLI-страниц по
  [контракту query](../../docs/contracts/SEMANTIC-QUERIES.md).
  Страницы одной ревизии сохраняют поля и порядок записей.
- Отчёт показывает статические прямые вызовы, а не число выполнений или
  динамическое профилирование. Отсутствие входящих вызовов не доказывает,
  что функция не используется вне выбранного корня. Builtin-цели показаны
  отдельно. Повторные специализации одного места вызова считаются один раз.
- Лимиты: вход 2 МиБ, до 128 документов, 1024 функций, 8192 мест вызова,
  выход 512 КиБ. У JSON-библиотеки дополнительно есть предел 65 536 узлов
  и глубина 128. Большой граф может достичь его раньше лимита байтов.
  Для такого графа укажите `--json-nodes 131072`.
- В отчёте показаны пути из входного индекса и его revision. Это снимок;
  SourceLens не открывает исходники и не удостоверяет их актуальность.
- Внешний текст HTML-экранируется; исходный JSON не вставляется в script.
  Ссылки ведут только на числовые якоря внутри отчёта.
- Успех — код 0; неверный ввод/параметры/файловая ошибка — код 2.
  Публикация через атомарную замену; до неё старый отчёт сохраняется.
  Выход, совпадающий с входом, в том числе через hardlink, отклоняется.

## Посмотреть и запустить

Откройте [готовый отчёт](report.html) двойным щелчком в браузере. Сервер,
интернет и установленный компилятор для просмотра не нужны.
[Вид отчёта](preview.png). Его исходные данные — индекс трёх модулей из
[demo](demo/main.vela): 12 функций, 25 мест вызова и три импорта.

Из корня репозитория Vela 0.10.0-dev.7 или новее на Windows x64:

```powershell
pwsh -File apps/source-lens/build.ps1
Start-Process apps/source-lens/report.html
```

Для другого проекта:

```powershell
$q = (& .\vela.cmd query apps/route-audit/main.vela) -join "`n"
if ($LASTEXITCODE -ne 0) { throw 'Query failed' }
[IO.File]::WriteAllText("$PWD/index.json", $q, [Text.UTF8Encoding]::new($false))
.\apps\source-lens\bin\source-lens.exe index.json report.html
```

JSON записывается в UTF-8 без BOM; перенаправление `>` в старом Windows
PowerShell может выбрать другую кодировку. Пути в индексе относятся к машине,
где выполнялся `query`; перенос HTML не обновляет их. Компилятор и MSVC нужны
для сборки, готовому executable — только Windows. DLL и Node.js ему не нужны.

## Историческая проверка на Vela 0.9.0

- **7/7 именованных тестов**, **31/31 интеграционная проверка**:
  [машинный отчёт](validation.json). Проверены точные метрики, ошибки с JSON-путём,
  дубликаты специализаций, неизвестные связи, лимиты ввода/вывода, UTF-8,
  HTML-инъекции, hardlink, сохранение старого файла и форматирование.
- Принудительный GC сохранил точные байты HTML: 20 922 байта,
  SHA-256 `467ca95f8abf66ffa28590d384e54f497d42d080fa5e095aa3692ec532f9f622`.
  Этот стресс-режим собирает память при каждом выделении; 28,3 с не являются
  временем обычного запуска. При параллельной сборке первый прогон превысил
  30 с; изолированный повтор прошёл с явно заданным бюджетом 60 с.
- Через CLI/LSP выполнено реальное переименование `target_link` →
  `call_target_link`: три совпавшие правки, проверка revision, отклонение
  устаревшего плана, последующая сборка. [Свидетельство](refactor-evidence.json).
- Через официальный SDK MCP прошли context/help/check/query/plan/test/build/
  run/read_output. План переименования `grade` затронул три файла демопроекта
  только в preview. HTML получен из ОС-песочницы, SHA-256 проверен, байты
  явно сохранены в [report-mcp.html](report-mcp.html) и совпали с native.
  [Результат](tooling-validation.json). Инструменты MCP в этом чате не
  обнаружены; это интеграционный SDK-тест, а не проверка нового агента.
- В браузере проверены внешний вид при узкой и широкой панели, фильтр `io`
  (2 функции), модуль rules (4 функции), поиск без совпадений, сброс,
  раскрытие связей и переход из отфильтрованной карточки к скрытой функции.
  Ошибок и предупреждений JavaScript нет. Скриншот сохранён выше.

Повторная проверка:

```powershell
pwsh -File apps/source-lens/build.ps1 -Test
node apps/source-lens/check-tools.mjs
```

Второй сценарий требует собранного `integrations/mcp`, его npm-зависимостей
и проверенного `build/mcp-execution/execution.json` из подготовки MCP execution.
Проверки приложения не заменяют release gate языка. Compiler/runtime не
менялись, полный `vela-dev verify` и выпуск архивов не повторялись.

## Впечатления от 0.9

Самое заметное улучшение — обратная связь при разработке. Вместо поиска
совпадений текста можно получить конкретное определение, вызовы и проверенный
план переименования. Raw-литералы позволили записать HTML/CSS/JavaScript
обычным многострочным текстом; форматтер сохранил их байты. Выдача MCP-артефактов
закрыла весь путь от сборки до файла, который можно открыть и сравнить.

В обработке данных всё ещё многовато вспомогательного кода: `decoded`,
`explain`, `field`, `string`, `number`. Для JSON boolean пришлось сопоставить
все семь вариантов `Value`: у курсора нет `as_bool`. Это аргумент за дополнение
библиотеки, а не за отказ от исчерпывающего match. `Result.map_err` после появления
callable должен сократить перевод ошибок, сохранив их пути.

Граница масштаба подтверждена запуском. Полный граф RouteAudit обработан,
а собственный граф SourceLens — **834 306 байт, 66 590 JSON-узлов** — отвергнут
стандартным парсером при лимите 65 536. Лимиты нужны, но раздельные ошибки
бюджетов и настраиваемые ограниченные параметры были бы полезнее одного
`JSON limit exceeded`. Дополнительно запросам пригодятся выбор нужных видов
записей и страницы, привязанные к одному revision.

Ещё одно наблюдение: тип функции в индексе бывает пустым у generic-шаблона,
хотя места его вызова содержат `Int` и `String`. SourceLens собирает эти типы
и не трактует пустые эффекты как доказательство чистоты. Для следующих
абстракций нужен явный статус полноты данных, а не вывод по пустой строке.

Порядок 0.10 менять не требуется. Сценарии для библиотеки, generics и
масштаба запросов внесены в [план](../../docs/ROADMAP.md) с сохранением
нынешних контрактов и будущего статуса. Методы и функции как значения
выглядят полезнее новых сложных конструкций или наследования.
