# BuildLens: контракт приложения

Анализ повторных запусков тестов: JSONL → JSON или автономный HTML.
Используется Vela 1.2 без изменений компилятора/std.

Каждая непустая строка содержит ровно `id`, `suite`, `name`, `status`, `duration_ms`.
Первые три — 1–256 байт UTF-8, status — passed/failed/skipped,
duration_ms — целое 0–86400000. Unknown/duplicate fields запрещены.
Пробельные строки пропускаются; BOM в начале, CRLF и последняя строка без LF допустимы.
Повтор id полностью валидируется, затем игнорируется: первое событие побеждает.
Тест определяется парой suite/name. Последний статус задаёт порядок файла.
Flaky — наличие passed и failed среди уникальных событий теста; skipped не влияет.
Это характеристика выборки, не статистический прогноз.

--suite выбирает точное имя набора, но проверяется весь вход. --top ограничивает
только строки отчёта, сводка считает все выбранные тесты. Порядок: latest failed,
затем flaky, затем остальные; внутри — max duration убывает, suite/name по UTF-8.
JSON детерминирован. Лимиты: 64 MiB входа, 64 KiB строки, до 100000 непустых
событий (--max-events), JSON depth 16 / nodes 128, блок чтения 16 KiB.
Агрегаты/Set id хранятся в памяти: O(уникальные события + тесты).
Reader закрывается при любом исходе. Выход публикуется атомарно после полной
проверки; прежний файл сохраняется при ошибках входа. Выход должен отличаться
от входа (включая aliases/hardlinks).
Конкурентная подмена путей другим процессом во время публикации не входит
в контракт; проверка идентичности выполняется до чтения и перед публикацией.
Ошибка очистки после успешной атомарной замены отдельно сообщает committed=true.

Коды: 0 готово/help; 1 готово, --fail-on-problem и есть failed/flaky;
2 ошибка аргументов, входа или записи.

Готовность: native check/build, named tests, независимые CLI literal oracles,
ошибки/границы/Unicode/escaping/сохранение файла и просмотр HTML в браузере.
Токены: дельта provider counters от запроса до явного финального среза;
cached/uncached/output отдельно. Работа над релизом 1.2 исключается.
