# PulseDeck — монитор сервисов на Vela

Текущий исходник использует task groups, awaitable HTTP и общую GUI-библиотеку
из серии **1.0.0-dev.5+**. Прикладные обвязки окон больше не копируются;
предикаты успеха сравнивают enum напрямую, строковые метки используются для вывода.
Настройки конечных точек проходят общий `http::from_url`; приложение сохраняет
GET-политику мониторинга. Остальные методы доступны в [HTTP API](../../docs/contracts/HTTP-API.md).
Архив 0.11 и исходные отчёты ниже — историческая прикладная проверка.

Нативное Windows-приложение проверяет несколько HTTP/HTTPS-сервисов, показывает
результаты по мере готовности и сохраняет JSON. Можно отменить запросы, повторить
проверку и закрыть окно во время загрузки. Завершённые результаты сохраняются.

## Запуск

Из корня репозитория:

```powershell
.\vela.cmd run apps/pulse-deck/build.vela
.\apps\pulse-deck\bin\pulse-deck.exe
```

Без аргументов открывается демо с локальным сервером, написанным на Vela.
Интернет не нужен. Из шести проверок **три успешны**, а три намеренно показывают
HTTP 500, неожиданный HTTP 404 и превышение размера ответа. Ожидаемый HTTP 404
у отдельного сервиса считается успехом.

`Run checks` повторяет проверки, `Cancel` отменяет незавершённые, `Save JSON`
сохраняет отчёт ещё раз, `Close` отменяет активные запросы и закрывает окно после
освобождения ресурсов. Отчёт автоматически сохраняется при завершении каждого
запуска; его путь показан под результатами. Прокрутка открывает остальные строки.

Готовый exe требует Windows 10+ x64, две DLL рядом с ним, каталог `assets/` и
доверенный curl >= 8.4. В демо используется системный `System32/curl.exe`.
Vela, MSVC, Python и Node для запуска собранного приложения не нужны.

Консольный режим:

```powershell
.\apps\pulse-deck\bin\pulse-deck.exe --headless
.\apps\pulse-deck\bin\pulse-deck.exe --headless --cancel-after 300
.\apps\pulse-deck\bin\pulse-deck.exe --config C:\checks\services.json --output C:\reports
```

`--output` задаёт существующий родительский каталог. Внутри создаётся уникальная
папка, содержащая `report.json`; по умолчанию родитель — `%TEMP%`. Чужие файлы и
ресурсы приложения не перезаписываются. Коды CLI: 0 — все статусы ожидаемые,
1 — есть неуспешные проверки, 2 — ошибка приложения/настроек, 3 — отменено.
Демо в консольном режиме ожидаемо возвращает 1. GUI после обычного закрытия — 0.

## Свои сервисы

Скопируйте [demo.json](demo.json), поставьте `demo: false`, укажите реальные порты
и адреса. Поля обязательны, дополнительные поля игнорируются:

```json
{
  "demo": false,
  "curl": "C:/Windows/System32/curl.exe",
  "ca_file": "",
  "concurrency": 3,
  "endpoints": [
    {"name":"My service","scheme":"https","host":"localhost","port":8443,
     "target":"/health","expect":200,"delay_ms":0,"timeout_ms":3000,"body_limit":4096}
  ]
}
```

Пустой `ca_file` означает системное доверие. Для собственного CA задайте абсолютный
путь к PEM. Отключения проверки TLS нет. Имя хоста не включает схему/путь;
`target` начинается с `/`. `delay_ms` — задержка перед допуском к очереди запросов;
тайм-аут отсчитывается от постановки самого HTTP-запроса. До 16 сервисов, до четырёх
запросов одновременно. Подробные бюджеты — в [контракте](CONTRACT.md).

Это один GET на сервис за запуск, без авторизации, POST, перенаправлений и
автоматических повторов. Успех проверяет статус, а не содержимое ответа.
Бинарные тела допустимы; отчёт содержит длину и SHA-256, но не сами данные.

## Проверки и устройство

```powershell
.\vela.cmd test apps/pulse-deck/vela.project --json
node apps/pulse-deck/verify.mjs
.\vela.cmd run apps/pulse-deck/debug-build.vela
node apps/pulse-deck/tooling-check.mjs
.\apps\pulse-deck\package.ps1
.\apps\pulse-deck\verify-package.ps1
```

Node и OpenSSL нужны только независимому тестовому HTTPS-серверу. Путь к OpenSSL
можно задать через `PULSE_OPENSSL`. Проверки не обращаются в публичный интернет.
Пакет создаётся в `dist/pulsedeck-1.0-vela-0.11.0-windows-x64.zip`.

| Файл | Назначение |
|---|---|
| [model.vela](model.vela) | JSON-настройки, типизированные состояния, отчёт |
| [engine.vela](engine.vela) | async-задержки, очередь HTTP, отмена и очистка |
| [main.vela](main.vela) | CLI, Win32 event loop, демонстрационный Vela-сервер |
| [общий GUI](../../native/gui/adapter.c) | Только Win32-контролы и доставка событий через ABI 1 |
| [tests.vela](tests.vela) | Именованные проверки модели |

Использованы `async fn`, вложенный `await`, `sleep_ms`, захваты замыканий,
`defer`, типизированные loop/task/outcome, `dyn http::Transport`, HTTP/HTTPS,
loopback-сервер, `panic` в generic test-helper, ресурсы манифеста и
`path::resource_base`. Проверены `--cache`, страницы query, `emit-c --debug` и
профиль. Сейчас `engine.vela` ожидает `async_io::fetch` внутри задачи; один
`task_group` управляет таймерами, очередью, отменой и очисткой. Низкоуровневые
HTTP-операции выполняет host bridge библиотеки. Win32 GUI и сетевой транспорт
этого приложения проверены только на Windows.
