# FieldDesk на Vela 0.10.0

Для такого приложения 0.10 уже даёт удобную основу. Модель, чтение, расчёты,
отчёт, сервисы и окно удалось разделить по модулям. Закрытые Sample и Settings
заставляют проходить проверку входа, а методы убирают часть длинных имён функций.
Наследование для этой задачи не понадобилось.

Особенно полезны замыкания и интерфейсы. Калибровка хранит настройки в явном
захвате. Один анализатор принимает источник байтов с нужными эффектами и работает
с файлом и памятью. Внешние сервисы выбираются на границе приложения. В тесте
можно записать полный сценарий, заменить выходной файл маркером и убедиться,
что playback выдаёт прежние байты, не трогая этот маркер.

Числа, типизированный JSON, bounded builder и атомарная публикация покрыли
прикладную задачу без изменения компилятора. При 5 и 40 повторах под принудительным
GC пик управляемой памяти был одинаковым — 23 442 байта. Это измерение конкретного
небольшого демо, не оценка RSS или всей нативной памяти процесса.

Что замедляло работу:

- **Обвязка replay.** Пришлось написать Exchange и несколько функций, которые
  разбирают общий Answer и отклоняют чужие варианты. Полезнее иметь библиотечные
  адаптеры каждого сервисного интерфейса с сохранением порядка журнала и причин
  ошибок. Динамический вызов по-прежнему требует эффекты интерфейса, даже когда
  выбранный Playback фактически работает только с памятью.
- **Нативное окно.** Размеры, текстовые буферы, шрифт, переносы Win32 и очередь
  событий пока собираются вручную. Найденная проблема отображения LF исправлена
  в приложении. Для следующего GUI нужны общий адаптер виджетов и типизированное
  событие изменения текста. Сейчас сводка обновляется по Analyze/Export.
- **Путь к своему exe.** Дочерняя проверка должна запускаться после переноса
  приложения. Стандартного API для пути исполняемого файла нет; пришлось добавить
  OS-примитив в C-адаптер. Эту потребность стоит закрыть вместе с ресурсами поставки.
- **Завершение с ошибкой.** В generic test-helper после `assert_true(false, ...)`
  анализ потока ещё требует возврат T. Сейчас используется недостижимый рекурсивный
  возврат, как в существующих тестах Vela. Нужен явно завершающий путь с контрактом
  cleanup и корректной диагностикой, прежде чем добавлять новый синтаксис.
- **Граница переименования.** Query/plan манифеста нашёл объявление transform и
  вызов из приложения. Вызов в tests.vela виден только в запросе от тестового
  корня. Это соответствует текущей границе импортного графа, но для рефакторинга
  проекта нужен охват test-entries либо явное предупреждение о неполноте.

Поле и метод не могут иметь одно имя. Внутренние поля вроде `raw_value` решают
это без изменения языка; сейчас я не стал бы менять правила ради короткого
getter. Похожим образом отсутствие литерала списка добавляет строки в настройку
CLI, но уступает по важности ресурсам и асинхронности.

Основной порядок развития менять не нужно. Следующим остаётся **0.11.1** —
event loop, задачи, сроки и отмена. Синхронный HTTP-прототип позволил подключить
локальный источник, однако не подходит для сетевой работы внутри отзывчивого
окна. Для 0.11.2/0.11.3 FieldDesk даёт конкретный следующий сценарий — загрузка
измерений с прогрессом, отменой и безопасным закрытием окна.

В roadmap добавлены прикладные критерии для 0.11.1, 0.11.2, 0.11.3, 0.11.4,
0.11.5 и 0.11.6. Типизированная обвязка replay и завершающая функция отмечены как
кандидаты, требующие контракта; они ещё не реализованы. Компилятор, стандартная
библиотека и архивы релиза 0.10.0 этой прикладной работой не изменены.

Проверены 17 именованных тестов, 19 CLI-сценариев, 8 loopback HTTP-сценариев,
нативное окно и браузерный отчёт. Новый MCP-сеанс, LSP, TLS, другие ОС, DPI-матрица
и чистая машина не проверялись. Полный compiler verify не повторялся, поскольку
семантика compiler/runtime не менялась. Артефакты проверки перечислены в
[README](README.md).
