# FieldDesk

Текущий исходник GUI переведён на общий [модуль](../../std/gui.vela) 1.0.0-dev.3.
Отчёты 0.11 ниже описывают прежнюю поставку.

Журнал измерений на Vela. Приложение калибрует значения, считает статистику
по станциям и создаёт автономный HTML-отчёт с поиском и фильтром превышений.
Данные в примере синтетические.

[Открыть готовый отчёт](demo-report.html) · [Покрытие возможностей](FEATURES.md) ·
[Впечатления и предложения](REVIEW.md)

## Запуск

Готовый файл `bin/fielddesk.exe` открывает нативное окно. Рядом должны лежать
`vela-gui.dll`, `vela-http.dll` и `assets/settings.json`. В окне можно изменить JSON-строки,
нажать **Analyze**, затем **Export HTML**. Путь сохранённого отчёта появится
внизу окна. Его можно открыть обычным браузером. Порог окна равен 25, gain — 1,
offset — 0. Окно читает эти настройки из ресурса рядом с exe. Путь к ресурсу
сохраняется при запуске из другого каталога. Настройки для пакетной обработки
задаются отдельным JSON-файлом.

Из корня репозитория:

```powershell
.\vela.cmd run apps/fielddesk/build.vela
.\apps\fielddesk\bin\fielddesk.exe --gui G:/Vela/apps/fielddesk/fielddesk-report.html
.\apps\fielddesk\bin\fielddesk.exe --demo G:/Vela/apps/fielddesk/demo-report.html --replay-check
.\apps\fielddesk\bin\fielddesk.exe apps/fielddesk/demo.json apps/fielddesk/demo.ndjson apps/fielddesk/report.html
```

Сборка требует Windows x64/MSVC и [собранный HTTP-адаптер](../../docs/contracts/HTTP-MULTI-1.3.md).
Скрипт сборки на Vela собирает GUI-адаптер, обновляет lock и собирает манифест. Для запуска готового приложения
компилятор, Python и Node.js не нужны. В пакетном режиме рядом с отчётом создаются
файлы `.worker.out` и `.worker.err` дочерней проверки.

## Формат данных

Одна запись на физическую строку:

```json
{"station":"Причал","value":28,"accepted":true}
```

Настройки:

```json
{"title":"Экспедиция","limit":25,"gain":1,"offset":0}
```

Итоговое значение — `value * gain + offset`. Превышением считается значение
строго больше `limit`. Записи с `accepted: false` учитываются как исключённые.
Считаются среднее, минимум, максимум и стандартное отклонение всей совокупности.
Демо даёт 9 принятых записей, 1 исключённую, 2 превышения, среднее 20.67 и
стандартное отклонение 6.39.

Пакетный режим читает файл потоком. `--replay-check` читает ограниченный снимок,
записывает ответы сервисов и повторяет обработку с побайтовым сравнением отчёта.
При повторе публикация и запуск процесса не выполняются. Журнал хранится в памяти.
Дочерний процесс проверяет целостность оболочки HTML, а расчёты проверяются тестами.

Код завершения — 0 при успехе, 2 при ошибке. Флаг `--fail-on-alert` возвращает 3
при превышениях после успешной публикации. Ошибка разбора сохраняет предыдущий
отчёт. Если уже после публикации не проходит дочерняя проверка, программа сообщает,
что отчёт сохранён, и возвращает 2.

## Загрузка измерений по HTTP и HTTPS

Передайте доверенный локальный `endpoint.json` и при необходимости отдельный
файл настроек измерений. Пустой `ca_file` выбирает системное доверие. Непустой
абсолютный путь указывает на PEM. Для совместимости необязательное поле
`curl` принимает абсолютный путь к доверенному curl 8.4+.

```json
{"scheme":"https","host":"localhost","port":8443,"target":"/measurements","timeout_ms":5000,"ca_file":""}
```

```powershell
.\apps\fielddesk\bin\fielddesk.exe --gui report.html --endpoint endpoint.json --settings apps/fielddesk/demo.json
```

**Load HTTPS** запускает загрузку и показывает время ожидания.
**Cancel** отменяет запрос. Пока запрос активен, редактор доступен, а
анализ, экспорт и повторная загрузка заблокированы. Если изменить текст во
время загрузки, ответ сохранит пользовательские правки. Успешная загрузка
очищает прежнюю сводку. Отчёт обновляется при экспорте.

Для пакетного сценария с HTTP на IPv4 loopback:

```powershell
.\apps\fielddesk\bin\fielddesk.exe --demo report.html --local-port 8080 --http-path /measurements --replay-check
```

Источник должен вернуть HTTP 200 и NDJSON. Предел ответа — 4096 байт. В окне
тот же предел действует после преобразования переносов строк в CRLF.
Пакетный запуск использует libcurl multi и общий тайм-аут 1500 мс. Replay
повторяет анализ полученного тела из памяти.

## Проверки и границы

```powershell
pwsh -NoProfile -File apps/fielddesk/verify.ps1
node apps/fielddesk/network-tests.mjs
```

Прошли 17 именованных тестов, 19 CLI-проверок и 8 локальных HTTP-сценариев.
Node нужен только для необязательного тестового HTTP-сервера. Вручную через
автоматизацию реального окна проверены ввод Unicode, анализ, экспорт, ошибка
с сохранением предыдущего файла и закрытие. В браузере проверены поиск, фильтр
превышений и пустая выборка. [CLI и GC](validation.json),
[сеть](network-validation.json), [интерфейс и инструменты](ui-tooling-validation.json).

Лимиты — 512 КиБ входного файла, 4096 байт строки, 2048 записей, 32 активные
станции и 1 МиБ отчёта. Редактор ограничен 4096 байтами UTF-8.
Текущая проверка окна выполнена на Windows x64 с настройкой масштаба этого
рабочего стола. [Контракт загрузки](../../docs/contracts/GUI-NETWORK.md).
