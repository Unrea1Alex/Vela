# Вызываемые значения и захваты — контракт 0.10.5

Контракт принят в 0.10.1 и реализуется рабочим компилятором 0.10.5.
Уточняет [RFC 0002](../rfcs/0002-generics-callables.md). Dynamic interface values
определены отдельно в [INTERFACES](INTERFACES.md), C callbacks — этап 0.10.9.

## Тип, вызов и эффекты

Тип: `fn(Int, String) -> Bool effects { io, state }`. Параметры упорядочены,
их типы и результат инвариантны: преобразования чисел, subtyping результата,
variadic/default-параметры и generic callable values не вводятся. Отсутствующий
`effects` означает пустое множество. Callable с меньшим множеством эффектов
допустим при ожидаемом большем; обратное преобразование отвергается.
Это единственное widening и не создаёт closure/environment.

Вызов `f(a, b)` вычисляет callable один раз первым, удерживает environment
в root, затем вычисляет аргументы слева направо. Проверка вызывающей функции
использует **тип callable**, даже если компилятору известен более чистый body.
Вызов не выделяет environment заново. Local binding callable-типа вызывается;
иной local binding по-прежнему скрывает одноимённую функцию и даёт E201.

Обычное имя функции может образовать callable без выделения environment.
Для generic-функции при получении значения все type/effect-аргументы указывают
явно; contextual inference по ожидаемому callable не вводится.
`Type::method` — unbound callable с self первым параметром. Получение bound
`value.method` запрещено: захват receiver оформляется closure. Foreign function
не преобразуется напрямую в callable; обычная Vela wrapper-функция сохраняет
все её обязательные эффекты и типизированные проверки.

## Параметры эффектов

Синтаксис:

```text
fn apply<T, effect E>(f: fn(T) -> T effects E, value: T) -> T effects E {
    return f(value);
}
```

`effect E` вводит отдельный вид generic-параметра с конечным множеством четырёх
эффектов. Имя не может совпасть с type-параметром или builtin-эффектом.
`effects E` — подстановка множества; `effects { io, E }` — объединение
конкретных эффектов и объявленных effect-параметров. Тела не могут добавлять
необъявленные эффекты. При проверке символического тела все ограничения
включения должны выполняться для **каждой** допустимой подстановки, а не только
для первой встретившейся специализации.

Компилятор проверяет пустую подстановку и по одной подстановке с полным
множеством для каждой переменной. Включение объединений при всех подстановках
следует из этих проверок. Эффектные переменные в языке можно только объединять
и передавать, поэтому конкретная операция не может условно зависеть от состава
эффектов.

В явном полном списке generic-аргументов type-аргумент записывается обычным
типом, effect-аргумент — `effects { io, state }`: например
`apply<Int, effects { io }>(f, 1)`. Список идёт в порядке декларации;
частичная подстановка не вводится. В неявном вызове E выводится только из
эффектов **непосредственных** callable-аргументов. Callable внутри List/struct
или параметра другого callable не является источником вывода E. Если E встречается в нескольких
аргументах, выбирается объединение их множеств. Если E присутствует лишь в
результате или в теле, вывести его нельзя — нужен полный явный список (E239).
Return-context и ambient effects вызывающей функции не являются источниками вывода.

Для однозначного вывода параметр callable с эффект-переменной использует
`effects E`, без объединения с другими effect-переменными/конкретными эффектами
в том же callable-типе. В возвращаемом callable и эффектах самой функции
объединение разрешено. Все явные подстановки проверяют включение actual ⊆ expected.
`Any`, callable shapes и effect parameters — разные понятия; Any не даёт права
вызвать значение. Monomorphization кеширует и type-, и effect-подстановку.

## Явные захваты

```text
let offset = 2;
let shift = fn [offset](x: Int) -> Int { return x + offset; };
```

Closure записывается `fn [имена захватов](типизированные параметры) -> Type
[effects ...] { body }`. Список захватов обязателен, в том числе пустой `[]`;
каждое имя — существующий lexical binding ровно один раз. Инициализаторы/алиасы
в списке, неявные захваты и конфликт с именами параметров запрещены (E238).
Имена функций/типов модуля разрешаются без захвата. Доступ к отсутствующему
lexical capture — E238, к вообще несуществующему имени — E203.

Захваты shallow-copy вычисляются в порядке списка при создании closure.
Скалярный `var` копируется с текущим значением; последующая запись в исходную
переменную не меняет capture. Внутри closure capture immutable; для локального
изменения создают `var`, для общего состояния явно захватывают List/Dict и
объявляют `state`. Это отличается от defer, который читает текущие bindings
при исполнении. Closure не удерживает stack frame или адрес локальной переменной.

Непустой capture list создаёт один managed environment; пустой closure и имя
функции не создают environment. Callable хранит code pointer и environment
pointer; его копии разделяют immutable environment. Descriptor трассирует все
поля, в том числе opaque payload, nested callable, dyn value и ForeignHandle
metadata. Code/descriptor живут до конца процесса. Результат closure и
временные аргументы rooted через defer/ensures по обычным правилам.

`return`/`?` внутри closure завершают **этот вызов closure**, не внешнюю функцию;
его defer выполняются один раз на структурированном выходе. `requires`/`ensures`
у анонимного closure в первой версии запрещены; у именованной функции остаются
действующие runtime-контракты. Вызов callable сохраняет эти проверки цели.
Panic/exit не разматывают lexical cleanup, как и в 0.9.

Самозахват ещё не инициализированного binding запрещён (E203). Именованная
рекурсия допустима; циклы через явно разделяемые коллекции допустимы и
собираются GC. Для каждого reentrant-вызова создаются собственные stack roots
и локальные значения, а разделяемые коллекции остаются общими. Никакого
автоматического lock, атомарности или потокобезопасности не появляется.

Захват ресурса удерживает metadata, но не продлевает его **открытое** состояние
и не переводит обязанность close автоматически. После close через любой alias
другие захваты видят закрытый handle; запрещённый FFI-вызов завершается до C
по действующему контракту. Closure может по-прежнему выполнять безопасные
действия, не использующие закрытый ресурс. GC не вызывает close/destructor.

## Границы и ошибки

Callable можно хранить/возвращать/передавать, помещать в List/enum/struct;
equality, Scalar-bound и dictionary keys для callable запрещены.
Callable и dyn values остаются внутренними типами. Отдельный
[CallbackHandle](CALLBACKS.md) из 0.10.9 передаёт нативному адаптеру
зарегистрированный дескриптор. Регистрация управляет root и отменой.

E201/E210 — несовместимый callable/арность; E209 — эффектный вызов без разрешённых
эффектов; E238 — capture/неподдержанная callable-форма; E239 — неверная или
невыводимая effect-подстановка; E217 — предел специализаций. Для E239 всегда
известен объявленный effect-параметр: это неверный аргумент в его позиции либо
невыводимое значение. Effect-аргумент на месте type-параметра — E210, неизвестное
имя конкретного эффекта — E206. Эффектная
несовместимость при передаче callable сообщает E209 с actual/allowed/missing.
Модель не обещает освобождение ресурсов по достижимости или отсутствие panic.
