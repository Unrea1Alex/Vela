# Методы с явным receiver — контракт 0.10.3

Контракт этапа 0.10.1, реализован в рабочем компиляторе 0.10.3.
Зависимость: [ENCAPSULATION](ENCAPSULATION.md). Методы не меняют модель памяти.

## Объявление

```text
impl Counter {
    pub fn next(self: Counter) -> Counter {
        var copy = self;
        copy.value = copy.value + 1;
        return copy;
    }
}
impl<T> Box<T> {
    pub fn get(self: Box<T>) -> T { return self.value; }
}
```

Это фрагменты объявлений; определения типов опущены. `impl` контекстен
на уровне декларации. Блок разрешён только в модуле владельца пользовательского
номинального struct/enum/distinct. Для одного типа допускается один inherent
`impl`; отдельные interface-реализации описаны в [INTERFACES](INTERFACES.md).
Нельзя добавить метод к чужому типу, builtin или алиасу типа.

Generic impl перечисляет все параметры владельца в том же порядке и с теми же
ограничениями, его receiver — точный `Owner<T...>`. Специализация для `Box<Int>`
и дополнительные условия impl не допускаются. Метод не имеет собственных
generic-параметров в первой версии. Фабрики/статические операции остаются
функциями модуля; каждый метод имеет первый параметр **`self: Owner`**.
`self` — обычное неизменяемое значение, не ссылка. За пределами этой позиции
оно не становится глобальным зарезервированным именем.

Метод private по умолчанию; `pub fn` доступен клиенту публичного владельца.
Публичный метод не раскрывает private-типы, включая generic-ограничения.
Поля и inherent-методы одного типа, а также варианты enum и inherent-методы
делят пространство имён: коллизия отвергается, даже если одно имя private.
Перегрузка по параметрам/эффектам запрещена. Тело проверяется в модуле владельца.

## Вызов и порядок вычислений

`value.method(a, b)` выбирает inherent-метод по точному номинальному типу value.
Эквивалентная явная форма: `Owner::method(value, a, b)`, для generic-типа —
`Owner<T>::method(...)`, через модуль — `api::Owner<T>::method(...)`.
Ни открытые импорты, ни имя локальной функции не добавляют кандидатов к этому
поиску. Поле callable-типа с тем же именем невозможно из-за правила коллизии.

Receiver вычисляется **один раз, первым**. Его shallow-copy сохраняется в
типизированном GC root; затем слева направо вычисляются остальные аргументы.
Затем проверяются requires, исполняется тело, вычисляется возвращаемое значение,
выполняются defer и ensures по действующим правилам. При раннем `?` в receiver
или аргументе следующие аргументы и метод не выполняются. Эффекты receiver,
аргументов и вызываемой сигнатуры объединяются обычным правилом E209.

Изменение скалярного поля локальной копии self не меняет вызывающую переменную;
новое значение возвращают явно и присваивают: `counter = counter.next()`.
Изменение вложенного List/Dict заметно всем aliases и требует `state`.
`&self`, `&mut self`, implicit borrow/move, автоконверсия и mutable receiver
со скрытой записью в вызывающую переменную запрещены.

`value.method` без вызова не создаёт bound closure. В 0.10.5 явная
`Owner::method` сможет обозначать unbound callable с receiver первым параметром;
захват конкретного объекта оформляется явным closure. До 0.10.5 функции и методы
не являются значениями. Нет автоматического выделения памяти на входе в метод.

## Ошибки и lowering

E233: чужой/неподдержанный владелец, повторный impl, неверный self, коллизия
или неподдержанный generic/static-метод. E223/E224: privacy/API. E201/E210:
неверные типы/арность. E209: недостаточные эффекты. Неизвестный метод — E203.
Диагностика указывает место выбора и related-объявление, если оно существует.

Checker разрешает владельца и цель до C backend. HIR хранит прямой SymbolId,
явный receiver и упорядоченные аргументы; оригинальные spans сохраняются.
Backend не ищет методы по текстовому имени. Query/rename связывают dot- и
qualified-вызовы с одним определением, не с одноимёнными методами других типов.
