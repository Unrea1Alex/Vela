# Запись и воспроизведение сервисов — контракт 0.10.8

Модуль `replay` принимает [явные сервисы](SERVICES.md) для файлов,
процессов, часов и энтропии. Клиент посылает типизированный запрос и получает
типизированный ответ. Операции имеют общий порядок в пределах одной записи.
Сторонние вызовы вне этого API остаются за пределами записи.

Recorder хранит до 1024 обменов в памяти. Перед вызовом проверяются наличие
места и отсутствие повторного входа. Один запрос вызывает одну операцию
выбранного сервиса. В запись входят аргументы и весь ответ, включая
типизированную ошибку. Запрос процесса сохраняет копию списка аргументов.
Строки неизменяемы, объём файлового ответа ограничен запросом и сервисом.
Снимок содержит завершённый префикс и пригоден для нескольких независимых
воспроизведений. Формат хранения на диске в этой версии не вводится.

Replay принимает тот же запрос и выдаёт записанный ответ. Сравниваются вид
запроса, строки пути и данных, размер, порядок и байты аргументов процесса,
каталог, пути вывода и тайм-аут. Сравнение путей идёт по переданным байтам.
Воспроизведение требует `state` и работает без файловой системы,
процессов, часов и энтропии ОС. Оно возвращает записанную реакцию на
публикацию и запуск процесса, не создавая соответствующие файлы и процессы.
Для чтения таких файлов клиент записывает отдельный запрос чтения.

При несовпадении запроса, лишнем вызове или завершении с пропущенными
операциями возвращается ошибка протокола с индексом обмена от нуля.
Первая такая ошибка сохраняется в сессии. Успешный `finish` означает,
что все обмены из снимка потреблены в порядке записи. Сценарий можно
повторить, создав новую сессию из исходного снимка.

Приёмка проверяет смешанную последовательность всех сервисов, совпадение
typed errors, неизменность записанных аргументов, две сессии из одного
снимка, несовпадение, лишний и пропущенный вызовы и отсутствие повторных
действий ОС. Речь идёт о детерминизме ответов на записанные запросы.
