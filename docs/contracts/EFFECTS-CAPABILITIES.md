# Эффекты и явно переданные сервисы — решение 0.10.1

Решение для 0.10. Сервисы из 0.10.7 описаны в [контракте](SERVICES.md).
Четыре существующих эффекта
и их значения сохраняются: `io=1`, `args=2`, `state=4`, `process=8`.
Отсутствующий effects — пустое множество. `effects` проверяет верхнюю границу
операций, а capability-параметр выбирает объект сервиса; ни то ни другое
не предоставляет прав ОС и не изолирует произвольную DLL.

## Решение по альтернативам

| Различие | Решение для 0.10/0.11 | Причина и проверка |
|---|---|---|
| Файлы, stdin/stdout | Существующий `io`, явный FileStore при подмене | Старые программы/каталог не переписываются; fake не трогает ОС |
| Время | Clock-параметр и OS-примитива `clock_millis` с `io` | Fake может иметь `state`; наблюдение ОС требует эффекта |
| Внешняя энтропия | Entropy-параметр и OS-примитива `entropy_u32` с `io` | Отдельный API для детерминированного PRNG |
| PRNG | Чистое преобразование seed → (value, seed) либо `state` при общем хранилище | Не требует внешней энтропии автоматически |
| Сеть | Network-параметр в 0.11.2; операции имеют `io`, плюс реально нужные state/process | Выбор транспорта явный; чужой FFI не становится pure |
| Приостановка | В 0.10 синхронных операций нет скрытого yield; решение о проверяемом async-признаке — 0.10.11 | До event-loop контракта не вводится фиктивный effect `async` |

Новые имена `net`, `time`, `random`, `async` в 0.10 **не вводятся** и как
эффекты отвергаются E206. Blocking OS call и приостановка задачи — разные вещи:
blocking-вызовы существуют, кооперативной приостановки пока нет. Контракт 0.10.11
обязан определить допустимость ожидания и операций в UI/callback до реализации
0.11.1; текущее решение не объявляет blocking io безопасным для UI-потока.
Появление другой модели эффектов позднее потребует отдельной миграции.

## Правило вызова

Для свободной функции/метода используется объявленный набор; для interface
вызова — набор интерфейсной сигнатуры; для callable — набор его статического
типа после подстановки effect-параметров. Эффекты вычисления receiver и
аргументов также входят в проверку. Required ⊆ Allowed; разность — E209.
Ни inline, ни известная более чистая impl, ни dynamic dispatch не меняют это
правило. Проверка тела impl требует Actual ⊆ Interface ceiling (E236).

Например, файловая и тестовая реализации Reader могут требовать `{io, state}`
и `{state}` соответственно. Общая операция Reader::read требует `{io, state}`
на обоих объектах; это сохраняет возможность подмены без изменения клиента.
Тест доказывает отсутствие реальных файловых операций наблюдением fake/replay,
а не выводом из этого широкого набора эффектов. У прямого fake-helper может
быть более узкая сигнатура. Свой объект-capability не закрывает доступ ко всем
остальным builtin: код с объявленным `io` всё ещё может вызвать `read_file`.

Локальная скалярная мутация и выделения immutable strings/closure environment/
interface box не приобретают `state` только из-за allocation. Все операции
с List/Dict, включая чтение и создание, сохраняют `state`. GC safepoints
не добавляют языкoвого эффекта и не выполняют пользовательский код/destructors.

## FFI, каталог и совместимость

Все существующие строки `vela/builtins.def` и ABI-классификации сохраняются
побайтно в 0.10.1; изменение их семантики не скрывается под новым интерфейсом.
Новые OS-примитивы в 0.10.7/0.11.2 добавляются только через этот каталог,
с проверкой обоих readers и явными effects/ABI. Их конкретные имена и
результаты входят в контракт соответствующего этапа, не придумываются здесь.

Каждый extern продолжает требовать `process` и `state`, а при I/O ещё `io`.
Wrapper или implementation не может «погасить» эти эффекты. Если интерфейс
разрешает лишь `{io, state}`, implementation через extern с `process`
отвергается; нужно явно расширить публичный потолок или использовать подходящую
стандартную OS-примитиву. `ffi_close` по-прежнему `{io, process, state}`,
`ffi_retain`/`ffi_release` — `{state}`. Правила borrowed String, shared close,
DLL ABI 1 и явного закрытия остаются из [FFI](FFI.md) и [FFI-ROOTS](FFI-ROOTS.md).

Старые effects sets в сигнатурах не меняются; old source → same effects.
В 0.10.5 новые effect-параметры — opt-in, их грамматика и вывод описаны в
[CALLABLES-EFFECTS](CALLABLES-EFFECTS.md). Нет пользовательских effect handlers,
ambient capability registry, скрытого внедрения сервиса или авторасширения
публичного контракта. Runtime-контракты requires/ensures не становятся
статически доказанными; запрет эффектов в них сохраняется.
