# Подменяемые сервисы — контракт 0.10.7

Правила эффектов и доступа заданы в
[EFFECTS-CAPABILITIES](EFFECTS-CAPABILITIES.md). Клиент принимает сервис
явным параметром. Сборка приложения выбирает реализацию ОС или тестовую
реализацию и упаковывает её в соответствующий интерфейс.

| Сервис | Операции | Эффекты интерфейса |
|---|---|---|
| Файлы | Ограниченное чтение байтов, атомарная публикация байтов | `io, state` |
| Процессы | Запуск argv с каталогом, выходными путями и лимитом ожидания | `io, process, state` |
| Часы | Получение миллисекунд Unix UTC с явным результатом ошибки | `io, state` |
| Энтропия | Получение беззнакового 32-битного значения в `Int` | `io, state` |

Файловая и процессная реализации ОС используют текущие модули `fs` и `process`.
Тестовые реализации хранят данные и ответы в памяти. Исчерпание тестовой
последовательности даёт явную ошибку. Часы возвращают настенное время, которое
может измениться при коррекции системных часов. Для измерения тайм-аутов
процессный адаптер сохраняет существующий монотонный отсчёт.

Детерминированный генератор получает seed явно и возвращает число и следующий
seed. Его арифметика ограничена модулем 2 147 483 647. Начальное значение
нормализуется в диапазон от 1 до 2 147 483 646. Генератор не использует время
и энтропию автоматически. Примитивы `clock_millis()` и `entropy_u32()`
имеют `io` и возвращают `IntResult`. На Windows энтропия поступает из
системного BCryptGenRandom. Псевдослучайная последовательность
`services::random_step` воспроизводима при одинаковом seed.

## Ограниченное чтение NDJSON

Принимается синхронный API чтения порций через один открытый файловый
дескриптор. Runtime отвечает за открытие, ограниченное чтение байтов и закрытие.
Vela собирает строки, проверяет UTF-8 после склейки порций и обрабатывает
CRLF, BOM и конец файла. Пустая порция обозначает конец файла.
Состояние чтения принадлежит одному дескриптору. Алиасы видят одно положение
и одно состояние закрытия. Закрытие явно на всех структурированных выходах.
Сборщик трассирует метаданные без вызова деструктора. Потоковый API
сохраняет пределы общего размера, отдельной строки и числа маршрутов.
Отчёт публикуется после успешного чтения и разбора всех строк.

Проверки используют одинаковый NDJSON через настоящий и тестовый источник,
порции размером в один байт для CRLF и многобайтового UTF-8, неверную последнюю
строку, точные границы лимитов и сохранение прежнего файла.

`stream_open(path, max_bytes)` проверяет размер открытого обычного файла.
`stream_next(handle, chunk_bytes)` читает до 8192 байт. Vela дополнительно
проверяет общий объём при чтении, в том числе если файл вырос после открытия.
В одном процессе допустимо до 128 открытых потоков. Поток удерживает
метаданные до явного `stream_close`. Закрытие инвалидирует все алиасы,
даже если ОС сообщила ошибку при закрытии. Эти handles принимают операции
потока. Проверка владельца защищает C FFI от передачи такого дескриптора.

`lines::next` принимает источник порций как callable и переносит его
эффекты. Положение и ошибка чтения общие для алиасов Reader. Повторный вход
в тот же Reader из его источника отвергается. Проверяется первый встретившийся
дефект, с физическим номером строки или абсолютным смещением ошибки UTF-8.

## Бюджет JSON

`json::parse` сохраняет исходные ограничения и тип ошибки. Новый
`parse_with_limits` принимает `Limits(bytes, depth, nodes)` и различает
превышение каждого предела. Максимумы составляют 16 МиБ, 128 уровней и
131 072 значения. Корень имеет глубину 0. Учитывается каждое JSON-значение,
включая объекты и массивы. Имена полей входят в бюджет байтов.
Defaults сохраняют 16 МиБ, 128 уровней и 65 536 значений.
Недопустимая конфигурация отвергается до разбора.

`json::as_bool(cursor)` возвращает Bool либо типизированную причину с
исходным путём. SourceLens предлагает явный предел числа узлов. Пределы
байтов приложения, глубины JSON и размера HTML сохраняются. Приёмка сравнивает
полный собственный индекс, превышающий прежний предел, на обоих бюджетах.
Негативные сценарии проверяют отказ до замены существующего HTML.
