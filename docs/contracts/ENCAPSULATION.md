# Закрытое представление типа — контракт 0.10.2

Контракт этапа 0.10.1, реализован в рабочем компиляторе 0.10.2.
Статус приёмки — в [roadmap](../ROADMAP.md). Действующая модель значений —
[MEMORY](../MEMORY.md); модуль — канонический исходный файл по [MODULES](MODULES.md).

## Объявление и доступ

Грамматика: `[pub] opaque struct Name<параметры> { поля }`.
`opaque` — контекстный модификатор непосредственно перед `struct`, а не новое
зарезервированное имя во всех выражениях. `pub struct` сохраняет открытые поля
и доступный клиенту конструктор. У `opaque struct` **все** поля закрыты;
модификаторы отдельных полей в первой версии запрещены. `opaque enum` и
`opaque distinct` не вводятся: закрытое enum-представление помещается в поле
opaque-структуры. Generic-параметры и ограничения следуют GENERICS/INTERFACES.

Пример объявления в модуле библиотеки:

```text
enum Storage { Empty, Value(Int) }
pub opaque struct Counter { storage: Storage }
pub fn counter(n: Int) -> Counter {
    return Counter(storage: Storage::Value(n));
}
```

Владелец Counter может конструировать его, читать поля и менять их по обычным
правилам `var`. Внешний модуль может назвать публичный тип, получить его от
публичной функции, копировать, передавать, возвращать и хранить в коллекции.
Внешние `Counter(...)`, `value.storage` и присваивание полю запрещены, в том
числе через alias, generic, метод или интерфейс. Даже пустая opaque-структура
не имеет внешнего конструктора. Нет implicit/default/zero-конструктора,
reflection, record-update или способа разобрать структуру через pattern.

Доступ определяется модулем объявления тела, а не местом инстанцирования.
Функция владельца с generic-параметрами сохраняет доступ; generic из чужого
модуля его не получает. Отдельный тестовый модуль — обычный клиент; test в
самом модуле владельца имеет обычный доступ этого модуля. Дружба модулей и
доступ «внутри пакета» не вводятся.

## Публичный API и инварианты

В закрытых полях разрешены private-типы владельца. Проверка E224 по-прежнему
рекурсивно запрещает private-типы в публичных параметрах/результатах,
открытых полях, вариантах публичных enum и публичных generic-ограничениях.
Публичная opaque-структура считается публичным номинальным типом; её скрытый
layout не раскрывается при этой проверке API. При анализе layout и GC,
напротив, обходятся **все** её поля: opaque не скрывает цикл значений и не
исключает private-поле из трассировки.

Фабрики — обычные функции, а не особый класс конструкторов. Их `requires` и
`ensures` остаются runtime-проверками. Компилятор обеспечивает границу доступа,
но не доказывает инвариант, записанный автором фабрики. Владелец отвечает за
все свои конструирующие пути; скрытие поля не делает его immutable.

## Копирование, совместимость и ошибки

Opaque — значение с тем же shallow-copy, что обычная структура. Копируются
скалярные поля, immutable string handles и handles коллекций/ресурсов.
Вложенная коллекция остаётся общей: чтение и запись требуют `state`. Никаких
автоматических clone, move, borrow, boxing или destructor здесь нет.
Присваивание всей переменной `var x: Counter` допустимо с тем же типом;
копия структуры сама по себе не получает новую идентичность ресурса.

Переход существующего `pub struct` в `pub opaque struct` — намеренно несовместимое
изменение API библиотеки: клиенты полей/конструктора должны перейти на функции.
Без такого изменения исходники 0.9 сохраняют семантику. Изменение скрытых полей
при неизменном API допускает пересборку прежнего клиента, но требует relock
зависимости и полной пересборки графа. Стабильный бинарный layout не обещается.

Внешний доступ к полю — E223; внешний конструктор — новый E232; утечка
private-типа — E224; цикл layout — E204; нарушение `let` — E213. Приоритет:
сначала доступ к типу, затем доступ к конструктору/полю, затем типизация.
Диагностики и наблюдаемые сценарии: [ABSTRACTIONS-VALIDATION](ABSTRACTIONS-VALIDATION.md).
