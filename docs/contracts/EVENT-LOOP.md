# Цикл событий, ожидание и отмена — решение 0.10.11

Контракт для реализации в 0.11.1. Работающий [цикл Notes](GUI-APPLICATION.md)
синхронно доставляет события на главный поток. Переход к ожиданию сохраняет
границу [C callbacks](CALLBACKS.md) и семантику действующих эффектов.

В 0.11 реализуются [цикл и типизированное ожидание](ASYNC-CANCELLATION.md).
Поддержанные операции и границы Windows указаны в контракте реализации.

## Поток и проверка приостановки

Кооперативные задачи исполняют Vela-код в одном потоке цикла. Native workers
выполняют ограниченную ОС-операцию и сообщают о завершении через очередь.
Им передаются собственные буферы операции. Managed-значения остаются в
потоке Vela, где сообщение о завершении превращается в типизированный результат.

Приостановка отмечается отдельной формой `async fn` и явным `await`.
Синхронные функции и существующие `fn(...)` сохраняют синхронный контракт.
Тип вызываемого асинхронного значения включает признак приостановки и
объявленные эффекты. `await` допустим только в асинхронном теле.
Эффекты исполнения задачи проверяются в месте запуска и ожидания.
Операции `io`, `args`, `state` и `process` сохраняют значения.

Вход из native WndProc только ставит событие в очередь. Пользовательский
UI-обработчик выполняется после возврата из WndProc. В UI-обработчиках и
задачах цикла запрещены синхронное чтение и запись файлов, чтение stdin,
запуск с ожиданием процесса, синхронная сеть и повторная прокачка очереди
окна. Вызов этих операций через вспомогательную функцию или callable также
отвергается. Компилятор должен распространять признак блокировки по графу
вызовов. Для неизвестной цели применяется консервативная проверка.
Не классифицированный extern считается потенциально блокирующим.
Для доступа к ОС обработчик использует асинхронный адаптер и явно ожидает ответ.
Проверенные короткие операции UI адаптера исполняются самим циклом.

## Задача и время

Созданная задача принадлежит области запуска. До первого запуска её
состояние `created`, затем `queued`, `running` или `waiting`.
Запрос отмены переводит её в `cancel_requested`. Терминальный исход
`Ok`, `Failed`, `Cancelled` или `TimedOut` публикуется ровно один раз.
Повторная отмена возвращает текущий исход запроса. Дочерние задачи
завершаются при выходе из области после отмены и уборки.

Ожидание регистрирует продолжение и возвращает управление циклу. Готовые
события обрабатываются FIFO. Тайм-аут использует монотонный дедлайн
от момента постановки операции. При конкуренции завершения и тайм-аута
выигрывает первое обработанное терминальное событие. Позднее сообщение
может подтвердить освобождение нативного буфера, но не меняет исход.
Тестовый монотонный источник управляется отдельно от настенных часов.

## Roots и закрытие

Продолжение удерживает receiver, захваты и живые локальные значения.
Захват и передача receiver используют действующие правила копирования.
Удержанный ForeignHandle остаётся общей метаданной. При отмене очередь
останавливает новые операции, запрашивает отмену в ОС и дожидается подтверждения
для уже переданных буферов. После этого активные `defer` выполняются один раз
в порядке LIFO. В cleanup запрещена приостановка.
Пока операция подтверждает отмену, цикл продолжает обрабатывать другие события.
Каждый асинхронный адаптер обязан определить, как остановить его нативную операцию.

Закрытие окна сначала прекращает приём пользовательских событий,
затем отменяет задачи окна и дожидается их cleanup. После этого цикл
отменяет C-регистрации и освобождает окно. Синхронный callback никогда
не ждёт задачу и не запускает вложенный цикл сообщений.

## План приёмки 0.11.1

| Проверка | Наблюдение |
|---|---|
| `await` в синхронном теле или `defer` | Диагностика до C |
| Блокирующий вызов через функцию и callable из UI | Диагностика с местом вызова и источником блокировки |
| Две задачи и ввод во время I/O | FIFO событий и отзывчивое окно |
| Отмена до запуска, во время ожидания и после результата | Один терминальный исход и правильный набор cleanup |
| Ровно на дедлайне и позднее сообщение ОС | Один результат по порядку событий |
| Receiver и захваты через принудительный GC | Живое состояние сохраняется до завершения |
| Закрытие окна с активной задачей | Все операции подтверждены, cleanup один раз, регистрация отменена |
| Worker с ошибкой и гонка закрытия | Отсутствуют обращения к освобождённым буферам и двойной close |
