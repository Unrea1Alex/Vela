# Индексированный снимок конфигурации 1.3.1b

`std/config_snapshot.vela` предоставляет закрытый `Snapshot` с индексом имён
верхнего уровня и отдельным списком ключей в исходном порядке. `std/config`
сохраняет публичный Config и прежние проверки. Снимок использует существующие
GC List/Dict и неизменяемые строки. Операции над коллекциями требуют `state`.

`from_value` принимает объект `json::Value`. Владелец снимка получает новые
List на каждом вложенном объекте и массиве. Ссылки на исходные изменяемые
контейнеры не остаются. Разделяемое поддерево копируется для каждого вхождения.
Порядок полей/элементов сохраняется. Строки можно разделять без копирования
байтов. Снимок публикуется после проверки всей копии.

`parse` разбирает JSON с теми же лимитами и возвращает исходный
`json::ParseError` в `Error::Json`. Он передаёт только что созданное дерево
индексу. `from_value` отклоняет повторный ключ, повреждённый UTF-8 в именах
или значениях и неконечный Float64 (NaN/inf). Оба входа ограничены глубиной
64 (корень имеет глубину 0) и 100000 посещениями значений. Цикл через List
завершается `DepthLimit` либо более ранним `NodeLimit`.
На построение снимка выделяется бюджет 8 MiB суммарных UTF-8 байтов в ключах
и строковых значениях (считая каждое вхождение). `parse` дополнительно ограничивает
исходный JSON 8 MiB. Выход за границы даёт typed limit, без частичного результата.

`keys` возвращает независимый List. `find` отличает отсутствующее поле от
явного JSON null. `required` возвращает Missing. `string`, `integer`, `boolean`
и `number` используют индекс напрямую и дают WrongType для другого JSON-варианта.
`number` читает только JSON Float64, как прежний Config. `allow_only` возвращает
первый неизвестный ключ в порядке исходного объекта. Для скалярного lookup
нет повторной проверки UTF-8, копирования объекта или создания нового `seen`.
`find`/`required` копируют только запрошенный агрегат, если он массив или объект.
Копирование уже проверенного поддерева не повторяет проверки и сохраняет порядок.

Приёмка: независимые fixtures на ошибки, циклы, границы и alias; скрытое
представление невозможно подделать. Проверить 2000 lookup после одной копии
на тех же 8/64/256 полях и один lookup на каждом размере для оценки входной
цены. Медиана medium с построением должна снижаться хотя бы на 20%, peak job
commit входит в +10% по [профилю 1.3.1](PERFORMANCE-1.3.md). Счётчики отдельно
подтверждают один проход конструирования. Windows/Linux/GC и native gate.
