# Интерфейс для инструментов

Активный интерфейс — `velac.cmd` / `bin/velac.exe`. Нативный компилятор поддерживает `check --json`, `symbols`, `emit-c`, `build`, `run` без Python. Служебный параметр `--source-name NAME` задаёт имя виртуального исходника независимо от временного пути. `python -m vela` — исторический frontend подмножества 0.2; его сообщения и кодирование JSON могут отличаться.

## Проверка с JSON

В 0.7 команда `vela test SOURCE|PROJECT --json` возвращает report schema 2:
ok/passed/failed/tests; у каждого теста name/source/span/status/exit_code,
stdout/stderr, stdout_encoding/stderr_encoding (utf8 либо hex), artifact_dir.
Status: passed, failed, timeout, build_error. Exit 0 — успех, 1 — провал теста,
2 — инфраструктура; ошибки исходника сохраняют diagnostic schema 1/exit 1.
Тесты выполняются в отдельных временных cwd; созданные ими файлы остаются в
указанном artifact_dir. Это обычное native-выполнение с правами пользователя.
Схема 1 старого project test является исторической. [Контракт](contracts/TESTING.md).

```powershell
.\velac.cmd check examples/invalid/missing_effect.vela --json
.\velac.cmd symbols examples/factorial.vela
```

Успешная проверка возвращает `schema_version: 1`, `ok: true`, путь `source` и пустой массив `diagnostics`. При ошибке языка `ok: false`, в массиве одна диагностика:

```json
{
  "code": "E209",
  "severity": "error",
  "message": "Call to 'print' requires undeclared effects: io.",
  "source": ".../missing_effect.vela",
  "span": {
    "start": 0,
    "end": 0,
    "line": 1,
    "column": 1,
    "end_line": 1,
    "end_column": 1
  },
  "notes": [],
  "details": {"callee":"print","required_effects":["io"],"allowed_effects":[],"missing_effects":["io"]},
  "related": []
}
```

Координаты выше иллюстративные. `start`/`end` — смещения Unicode code points в нормализованном исходнике, полуоткрытый интервал. Строки и столбцы начинаются с 1. CRLF и одиночный CR преобразуются в LF, UTF-8 BOM удаляется. Это **не** смещения байтов и не UTF-16 позиции LSP. Адаптер редактора должен явно преобразовывать координаты. При ошибке доступа к файлу или декодирования возвращается `E900`; координат исходника у неё нет.

Нативный JSON записывается UTF-8: не-ASCII символы сохраняются, кавычки, обратная косая черта и управляющие символы экранируются. Потребитель должен декодировать UTF-8 независимо от кодовой страницы терминала. Нельзя определять категорию ошибки по английскому тексту: используйте `code`.

В 0.4 диагностики дополнены `details` и `related` без смены schema_version.
E201 сообщает `expected_type`/`actual_type`; E209 — `callee`, `required_effects`,
`allowed_effects`, `missing_effects`; E216 — `missing_variants` в порядке объявления.
`related` содержит `{message,source,span}` для связанных объявлений. Поля применяются
там, где такая информация имеется; пустые объект/массив допустимы. Человеческий вывод
включает соответствующие пояснения и позиции. [Полный контракт](contracts/DIAGNOSTICS.md).

## Форматирование

```powershell
.\velac.cmd fmt examples/collections.vela
.\velac.cmd fmt examples/collections.vela --check
.\velac.cmd fmt examples/collections.vela --write
```

Без флага команда выводит канонический UTF-8/LF в stdout. `--check` возвращает 0
для уже отформатированного файла, 1 при необходимости форматирования и ничего
не записывает. `--write` атомарно заменяет исходник после проверок. Флаги взаимоисключающие,
`-o` для fmt не поддерживается. C-компилятор не нужен. Ошибки синтаксиса/UTF-8
оставляют исходник неизменным; семантически ошибочный, но разбираемый исходник
форматировать можно. [Правила и гарантии](contracts/FORMATTER.md).

## Индекс символов

`symbols` сначала проверяет всю программу, затем выдаёт определения перечислений, параметры функций, типы результатов, эффекты, строку объявления и число контрактов. `contracts.verification` равен `runtime`: контракты проверяются при исполнении, не доказываются статически. Это пригодно для просмотра структуры программы; граф использования символов, стабильные ID и автоматический рефакторинг пока не реализованы.

В 0.3 JSON дополнен массивами `structs` (имена и поля с типами) и `distinct_types`
(имена и базовые типы). Типы коллекций выводятся канонически, например
`Dict<NodeId,List<String>>`. `schema_version` остаётся 1: новые поля добавлены
совместимо, прежний `enums` содержит только перечисления.

В 0.5 индекс содержит конкретные generic-экземпляры с каноническими именами,
например `Box<Int>` и `identity<String>`. Неинстанцированные шаблоны не являются
проверенными функциями и не включены в массив functions. ID C-символов не служат
публичными идентификаторами индекса. Диагностика внутри интерполяции указывает
на исходное выражение, включая Unicode code-point координаты.

## Исторический Python API (только подмножество 0.2)

```python
from vela.compiler import analyze, compile_c
from vela.source import Source, Diagnostic

source = Source("example.vela", "fn main() -> Int { return 0; }")
program = analyze(source)  # immutable checked IR
c_text = compile_c(source)  # standalone C11 text
```

При некорректной программе выбрасывается `Diagnostic`. Для вывода используйте `error.render(source)` или `error.to_dict(source)`. API не запускает компилятор и не читает пользовательские файлы; генератор C загружает поставляемый ресурс runtime из пакета. `vela.driver.build(source, output_path)` выполняет отдельный шаг нативной сборки.

Формат IR внутренний и пока может меняться. Схема JSON имеет явную версию; несовместимые изменения должны менять `schema_version`.
## Модули и MCP в 0.7.0

В MCP 0.7 отдельно включаются vela_build/vela_test/vela_run. Они используют
проверенную при старте LPAC/Job-песочницу Windows, частный снимок и ограниченный
toolchain. Run принимает только выданный artifact_id. Если backend недоступен,
контекст сообщает execution:false и причину, остаются пять инструментов анализа.
Это отличается от прямого native CLI с правами пользователя; см.
[контракт выполнения](contracts/MCP-EXECUTION.md).
artifact_id идентифицирует executable. Выдача созданного HTML/изображения/файла
не реализована; для сохраняемого результата сейчас нужен разрешённый native CLI.
Механизм файловых артефактов остаётся планом 0.9.9, без нового инструмента в 0.7.0.

check/build/run/symbols/emit-c загружают граф импортов; fmt обрабатывает один файл
или собственные файлы манифеста с --check/--write. test запускает явные test entries.
Контракт команд: [BUILD-PROTOCOL](contracts/BUILD-PROTOCOL.md).
Диагностика сохраняет путь и Unicode-координаты каждого файла. Коды: E221 —
импорт/предел графа; E222 — неоднозначность/alias; E223 — private доступ;
E224 — private тип в public API. Выходной файл не может совпадать с любым
исходником графа по пути или файловой идентичности.
