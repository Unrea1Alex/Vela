# Язык Vela 0.7.0

Версия 0.6 добавила модули (раздел ниже), манифесты
[PROJECT-FORMAT](contracts/PROJECT-FORMAT.md) и чистый `sha256(String)->String`
для точных байтов строки. Возвращает 64 lowercase hex символа; результат живёт
в process region. Единственный каталог сигнатур — `vela/builtins.def`.

## Синхронный C FFI (реализован в этапе 0.7.5)

extern "adapter.dll" fn sum(x: Int) -> Int effects { state, process };
объявляет внешний C-символ; pub extern открывает его импортирующим модулям.
Поддержаны Windows x64/MSVC, ABI 1 из [ffi.h](../vela/ffi.h), до 16 аргументов.
Типы: Int/int64_t, Int32/int32_t, Float64/double, Bool/int32_t (только 0/1),
ForeignHandle/void*, String/VelaBytes только на входе и Unit/void только на выходе.
Агрегаты, distinct, generics, контракты, callbacks и произвольные указатели запрещены.
Обязательны эффекты state и process; io объявляется для внешнего ввода/вывода.

Int32 — carrier без арифметики/Scalar/неявного приведения: int32_from_int возвращает
Int32Result с проверкой диапазона; int32_to_int расширяет точно. Строки заимствуются
только до возврата из вызова, readonly, с длиной в байтах и возможным NUL.
ForeignHandle нельзя изготовить из числа; ffi_is_null проверяет null, ffi_close
вызывает явный destructor и закрывает все копии handle. Повторное закрытие —
WriteResult::Err; передача закрытого/чужого handle — located panic 70.
ffi_load позволяет проверить доступность/ABI через WriteResult.

DLL загружается только рядом с executable; для run/test используйте native-записи
манифеста и lock. Режим округления восстанавливается после возвращения из C.
FFI — граница доверия native-коду; ABI version не доказывает корректность сигнатуры,
ownership или безопасность библиотеки. Полный [контракт FFI](contracts/FFI.md).

## Пользовательские generics (0.5.2)

Функции, struct и enum поддерживают параметры типов: `fn id<T>(x: T) -> T`,
`struct Box<T> { value: T }`, `enum Maybe<T> { Some(T), None }`.
Вызов `id(42)` выводит T из аргумента; `id<Int>(42)` задаёт его явно.
Конструкторы требуют типов: `Box<Int>(value: 42)`, `Maybe<Int>::Some(42)`.
В образце match достаточно `Maybe::Some(x)`: тип x известен из проверяемого значения.

Ограничения `T: Any`, `T: Scalar`, `T: Number` проверяются при инстанцировании.
Scalar включает Int/Float64/Bool/String и distinct-обёртки; Number — Int и Float64.
Нет вывода из ожидаемого результата, частичного задания параметров, перегрузки
или неявных преобразований. Неиспользованное generic-тело проверено синтаксически;
семантическая проверка выполняется для каждого используемого конкретного экземпляра.
Все обычные функции проверяются, даже если не вызываются.
Полные правила, идентичность и пределы: [GENERICS](contracts/GENERICS.md).

## Option, Result, match-выражения и `?` (0.5.3)

Prelude содержит `Option<T>` (Some/None) и `Result<T,E>` (Ok/Err).
Старые IntResult/StringResult/WriteResult остаются отдельными типами.
`match value { Result::Ok(x) => x, Result::Err(_) => 0 }` возвращает значение;
все ветви обязаны иметь один тип. Старый match с блоками остаётся инструкцией.
Scrutinee вычисляется один раз, затем вычисляется только выбранная ветвь.

`value?` извлекает Some/Ok или возвращает None/Err из всей функции. Функция должна
возвращать тот же generic-тип Option/Result; тип успеха может отличаться, тип ошибки
Result должен совпадать. Постусловия выполняются и при таком раннем возврате.
В requires/ensures `?` запрещён. Оператор не добавляет эффект и не закрывает ресурсы.
Подробности и миграция старых результатов: [ERRORS](contracts/ERRORS.md).

## Циклы for (0.5.4)

`for value in items { ... }` обходит List<T>, IntList или StringList и требует
`state`. На входе создаётся поверхностная копия элементов: изменения исходного
списка не меняют обход; вложенные ссылочные поля остаются общими.
`for i in start..end` обходит возрастающий полуинтервал Int, `..=` включает конец.
Границы вычисляются один раз слева направо; обратный диапазон пуст, Int.MAX безопасен.
Диапазоны пока существуют только в синтаксисе for.

Переменная цикла неизменяема и видна только в его теле. `break;` завершает ближайший
цикл, `continue;` переходит к следующей итерации, в том числе внутри match.
За пределами цикла они запрещены. Подробности стоимости snapshot, областей видимости
и переходов: [CONTROL-FLOW](contracts/CONTROL-FLOW.md).

## Программа и объявления

Программа состоит из входного UTF-8 модуля и явно импортированных модулей.
Файл содержит импорты и объявления `enum`, `struct`, `type`, `fn`; исполняемой
инициализации на уровне модуля нет. Комментарии начинаются с `//`. Идентификаторы
состоят из ASCII букв, цифр и `_`, но не начинаются с цифры; регистр значим.
Точка входа — `fn main() -> Int` или `fn main() -> Unit` без параметров во входном
модуле. Функции и типы доступны до текстового объявления внутри своего модуля.
Манифест задаёт entry и локальные зависимости; сам по себе соседний `.vela` файл
не подключается. Подробности: [MODULES](contracts/MODULES.md), [PROJECTS](PROJECTS.md).

```text
enum Measurement {
    Ready(Int, String),
    Missing,
}

fn double(value: Int) -> Int {
    return value * 2;
}

fn main() -> Unit effects { io } {
    print(double(21));
}
```

Имена объявлений уникальны в модуле. При разрешении имён собственное объявление
имеет приоритет перед открытыми импортами, затем используется prelude; неоднозначные
импорты дают диагностику. Имена встроенных типов и функций зарезервированы для
верхнеуровневых объявлений во всех модулях. Межмодульный доступ
разрешён только к `pub` объявлениям. Все параметры и возвращаемые типы функций
указываются явно. Возврат `Unit` можно написать как `return;` или оставить неявным
в конце тела. Для остальных типов анализ требует возврат на каждом пути.
Бесконечность `while true` не доказывается: после цикла анализ допускает продолжение.

## Типы

| Тип | Значения |
|---|---|
| `Int` | От `-9223372036854775808` до `9223372036854775807` |
| `Float64` | IEEE binary64; подробный контракт в NUMBERS |
| `Bool` | `true`, `false` |
| `String` | Неизменяемые байты с длиной; UTF-8 не гарантирован произвольным I/O |
| `Unit` | Единственное пустое значение, результат процедур |
| `IntList` | Общая изменяемая ссылка на динамический список `Int` |
| `StringList` | Общая изменяемая ссылка на динамический список `String` |
| `enum` | Один из объявленных вариантов с нулём или несколькими полями |
| `struct` | Номинальное значение с именованными полями |
| `distinct` | Номинальная обёртка Int, Float64, Bool или String |
| `List<T>` / `Dict<K,V>` | Общие изменяемые коллекции с проверяемыми типами элементов |

Неявных преобразований нет. Перечисления и структуры имеют разные типы даже при одинаковых полях. Предопределены `IntResult { Ok(Int), Err(String) }`, `StringResult { Ok(String), Err(String) }`, `WriteResult { Ok, Err(String) }`. Обобщённые коллекции встроены; пользовательские generic-объявления описаны выше. Псевдонимов типов пока нет.

Float64 доступен в версии 0.7.0: `1.25`, `1e3`, `-0.0`; + - * /
и сравнения требуют двух Float64. `%` и диапазоны остаются Int-only. Неявного
смешения с Int нет. Деление Float64 на ноль даёт infinity/NaN; переполнение
литерала отклоняется E205 до backend. NaN не равен самому себе. Float64 и его
distinct-обёртки запрещены в ключах Dict. Разбор возвращает FloatResult,
преобразование в Int — IntResult; формат `display` использует 17 значащих цифр.
Полные правила округления, locale, нечисловых значений и JSON:
[NUMBERS](contracts/NUMBERS.md). План совместимой миграции строк:
[TEXT-BYTES-PATH](contracts/TEXT-BYTES-PATH.md).
Формат с заданным количеством знаков и библиотечная математика, включая sqrt,
пока не реализованы. Они запланированы в ROADMAP 0.8.7–0.8.8; существующий
display не является форматом с двумя знаками после запятой.

Библиотечные Bytes/Text/Path и операции JSON, файлов, процессов, CLI и конфигурации
в 0.7 находятся в явно импортируемых [стандартных модулях](STDLIB.md). Это обычный
Vela-код с Result<T, Error>, а не неявный prelude. Публичные поля обёрток пока
доступны, поэтому операции проверяют инварианты на границе. Гарантия UTF-8 не
распространяется на старый String или произвольный результат read_file.

## Переменные и области видимости

В 0.7 доступны декларации `test "имя" effects { state } { ... }` и
`assert_true(Bool, String)`. Effects необязателен и по умолчанию пуст; тест
возвращает Unit, не принимает параметры и не экспортируется. `test` является
контекстным словом на уровне модуля. Имена уникальны в модуле, непусты, до 256
UTF-8 байтов без NUL; максимум 256 тестов на модуль. Assert проверяется при
выполнении, при неуспехе сообщает координаты и завершает процесс с 70.
`vela check` принимает файл только с тестами; build/run требуют main. Команда
`vela test FILE` запускает декларации входного модуля отдельно, продолжая после
падения. Таблицы и дополнительные assertions: std/testing.vela.
Контракт и JSON report schema 2: [TESTING](contracts/TESTING.md).

```text
let initial: Int = 10;
let label = "counter";
var current = initial;
current = current + 1;
```

`let` неизменяем, `var` допускает присваивание того же типа. Аннотация локальной переменной необязательна; тип выводится из обязательного инициализатора. Параметры функций и привязки `match` неизменяемы. Повторное объявление в той же области запрещено, во вложенном блоке разрешено затенение. Переменная недоступна за пределами своего блока. Имя `result` зарезервировано для постусловий, `_` — для отброшенного поля шаблона.

Локальная переменная с именем функции скрывает её в своей области; попытка вызвать эту переменную отклоняется. Функции не являются значениями первой категории.

## Выражения и арифметика

От высокого к низкому приоритету:

| Операции | Типы и результат |
|---|---|
| Вызов, доступ к полю, скобки | `f(a, b)`, `value.field`, `(expression)` |
| `-`, `!` | Отрицание `Int` или `Float64`, отрицание `Bool` |
| `*`, `/`, `%` | `Int × Int → Int` |
| `+`, `-` | `Int × Int → Int` |
| `<`, `<=`, `>`, `>=` | `Int × Int → Bool` |
| `==`, `!=` | Одинаковые Int, Float64, Bool, String или одинаковые distinct-типы → Bool |
| `&&` | `Bool × Bool → Bool` |
| `||` | `Bool × Bool → Bool` |

Бинарные операции левоассоциативны. Цепочка `a < b < c` не является сокращением двух сравнений и отклоняется по типам. Все операнды и аргументы вычисляются слева направо. `false && x` и `true || x` не вычисляют `x`.

Целочисленное деление округляется к нулю, остаток имеет знак делимого: `-7 / 3 == -2`, `-7 % 3 == -1`. Переполнение — ошибка выполнения с кодом завершения 70. Деление на ноль — такая же ошибка. `MIN / -1` переполняется, а `MIN % -1` возвращает математически корректный ноль. Проверки включены и при оптимизированной сборке.

Десятичные литералы допускают ведущие нули; восьмеричной интерпретации нет. Литералы за границей `Int` отклоняются до сборки. Выражение как самостоятельная инструкция должно иметь тип `Unit`: результат остальных выражений нужно сохранить или обработать.

## Строки

Литералы заключаются в двойные кавычки и поддерживают `\n`, `\r`, `\t`, `\0`, `\"`, `\\`. Физический перенос строки внутри литерала запрещён. Равенство сравнивает байты с учётом длины, включая встроенный нулевой байт; нормализация Unicode не производится. `print` выводит UTF-8 байты и добавляет перевод строки. На Windows перевод строки при выводе через CRT соответствует текстовому режиму ОС. Консоль должна поддерживать UTF-8 для отображения нелатинских символов.

Доступны `str_len(s)` (байты), `str_byte(s, index)` (0–255), `str_slice(s, start, end)` (полуоткрытый диапазон), `str_concat(a, b)`, `str_from_byte(byte)` и `int_to_string(number)`. Все они не имеют внешних эффектов. Индексы и размеры проверяются; ошибка даёт код 70. Строка — неизменяемая последовательность байтов: литералы имеют UTF-8, но байтовые операции и чтение файла могут создать произвольные байты, включая NUL. Срез сохраняет время жизни исходных данных до завершения процесса. Полная модель описана в [MEMORY.md](MEMORY.md).

## Управление потоком

```text
if n < 0 {
    print("negative");
} else if n == 0 {
    print("zero");
} else {
    print("positive");
}

var i = 0;
while i < 3 {
    print(i);
    i = i + 1;
}
```

Условие обязано иметь тип `Bool`. `if` и `while` — инструкции. `match` поддерживает
инструкцию с блоками и выражение со значениями ветвей (см. раздел Option/Result).
`for` обходит коллекцию либо целочисленный диапазон; `break` и `continue` действуют
на ближайший цикл, в том числе внутри match. Недостижимые инструкции после
безусловного выхода отклоняются. [Контракт циклов](contracts/CONTROL-FLOW.md).

## Перечисления и match

```text
let value = Measurement::Ready(42, "pixels");
match value {
    Measurement::Ready(number, unit) => {
        print(number);
        print(unit);
    }
    Measurement::Missing => {
        print("No measurement.");
    }
}
```

У конструктора типы и число аргументов должны совпадать с объявлением. Вариант без полей можно записать `Measurement::Missing` или `Measurement::Missing()`.

`match` вычисляет значение один раз и требует ровно одну ветвь для каждого варианта. Нельзя использовать общий wildcard вместо вариантов: добавление нового варианта должно выявлять все требующие изменения сопоставления. Отдельное поле разрешено игнорировать через `_`: `Measurement::Ready(number, _)`. Вложенные значения разбираются вложенным `match`. Варианты с данными хранят поля по значению, поэтому рекурсивные циклы типов запрещены.

## Эффекты и встроенные функции

Отсутствие `effects` означает пустое множество эффектов. Доступны `io`, `args`, `state` и `process`.

```text
fn main() -> Int effects { io, args } {
    match arg_int(0) {
        IntResult::Ok(n) => { print(n * 2); return 0; }
        IntResult::Err(message) => { print(message); return 2; }
    }
}
```

| Функция | Эффекты | Поведение |
|---|---|---|
| `print(Int / Float64 / Bool / String) -> Unit` | `io` | Одно значение и перевод строки в stdout |
| `arg_count() -> Int` | `args` | Число аргументов без имени программы |
| `arg_int(index: Int) -> IntResult` | `args` | Разбор аргумента с индекса 0; отсутствие или ошибка дают `Err` |
| `parse_int(text: String) -> IntResult` | нет | Разбор всей строки как десятичного `Int` |
| `arg(index: Int) -> StringResult` | `args` | Аргумент как строка, индекс с нуля |
| `eprint(text: String) -> Unit` | `io` | Строка и перевод строки в stderr |
| `read_file(path: String) -> StringResult` | `io` | Всё содержимое файла, без перекодирования |
| `write_file(path: String, content: String) -> WriteResult` | `io` | Создать или перезаписать файл байтами |
| `replace_file(from: String, to: String) -> WriteResult` | `io` | Переместить файл с заменой назначения |
| `remove_file(path: String) -> WriteResult` | `io` | Удалить один файл |
| `absolute_path(path: String) -> StringResult` | `io` | Абсолютный путь |
| `temp_dir(parent: String) -> StringResult` | `io` | Создать уникальную временную папку; пустая строка выбирает папку ОС |
| `remove_dir(path: String) -> WriteResult` | `io` | Удалить пустую папку |
| `env(name: String) -> String` | `process` | Значение переменной окружения, пустая строка при отсутствии |
| `process_run(arguments: StringList) -> Int` | `process, state` | Запустить программу и дождаться завершения; элемент 0 — executable |
| `process_run_to_stderr(arguments: StringList) -> Int` | `process, state` | То же с перенаправлением stdout ребёнка в stderr родителя |
| `exit(code: Int) -> Unit` | `process` | Завершить процесс с кодом 0–255 |
| `platform() -> String` | нет | `windows` или `posix` |

Процессы запускаются без shell с наследованием окружения и потоков. Отрицательное значение `process_run` означает ошибку запуска/ожидания; на POSIX ошибка `exec` в ребёнке даёт 127. Возможны платформенные коды аварийного завершения больше 255; их нельзя напрямую возвращать из `main -> Int`. Чтение и запись файлов закрывают дескриптор до возврата. `write_file` сам по себе не атомарен; драйвер компилятора пишет во временный файл и применяет `replace_file` после успеха. Функция `exit` не имеет отдельного типа `Never`, поэтому анализ возвратов может требовать следующий `return`.

Разбор допускает один начальный `+` или `-`, затем хотя бы одну ASCII цифру. Пробелы, лишние символы, пустая строка и выход за границы `Int` дают `Err`. Отрицательный или отсутствующий индекс аргумента даёт `Err`. Текст ошибок предназначен для человека; для будущего устойчивого API следует ввести отдельные варианты ошибки.

## Динамические списки

Для семейства `ints` тип списка — `IntList`, элемента — `Int`; для `strings` — `StringList` и `String`. Все операции требуют `state`:

| Операция | Результат |
|---|---|
| `ints_new()` / `strings_new()` | Пустой список |
| `ints_len(list)` / `strings_len(list)` | Число элементов |
| `ints_get(list, index)` / `strings_get(list, index)` | Элемент с индекса 0 |
| `ints_set(list, index, value)` / `strings_set(...)` | Заменить существующий элемент, `Unit` |
| `ints_push(list, value)` / `strings_push(...)` | Дописать элемент, `Unit` |
| `ints_truncate(list, length)` / `strings_truncate(...)` | Сократить длину, `Unit`; увеличивать нельзя |
| `strings_join(list, separator)` | Новая строка из элементов с разделителем |

Копирование переменной или передача списка в функцию копирует ссылку: изменения видны через все ссылки. `let` запрещает заменить саму ссылку, но не запрещает изменение списка через неё. Проверка эффекта `state` делает это наблюдаемое изменение явным. Сравнение списков через `==` отсутствует. Все индексы проверяются; операции за пределами списка завершают процесс с кодом 70. Контракты не могут читать списки, поскольку это требует `state`.

Проверка эффектов действует через сигнатуры вызовов. Локальные изменения `var` не являются внешним эффектом. «Без эффектов» не означает отсутствие арифметических ошибок, ошибок контрактов, переполнения стека или бесконечного выполнения.

## Контракты

```text
fn increment(n: Int) -> Int
    requires n < 9223372036854775807;
    ensures result == n + 1;
{
    return n + 1;
}
```

После сигнатуры допускается несколько `requires expression;` и `ensures expression;`. Все выражения имеют тип `Bool`. В них доступны параметры, а в `ensures` также `result`. Локальные переменные тела недоступны. Функции с непустыми эффектами вызывать в контрактах нельзя.

Предусловия проверяются по порядку перед телом, постусловия — по порядку перед возвратом уже вычисленного результата. Провал останавливает процесс с кодом 70 и координатами условия. Числовая ошибка внутри самого контракта также останавливает выполнение. Статической верификации и `old(...)` пока нет; параметры в любом случае неизменяемы.

## Завершение программы

`main -> Unit` означает код завершения 0. `main -> Int` должен вернуть число 0–255; остальные значения дают ошибку runtime, а не неявное усечение. Нарушение контракта, переполнение, деление на ноль и ошибка записи в stdout завершают процесс с кодом 70. Пользовательская программа тоже может явно вернуть 70, поэтому при диагностике учитывайте stderr.

Код 1 CLI означает ошибку языка; код 2 — ошибку файлов, аргументов CLI или сборки. Команда `run` после успешной сборки возвращает код самой программы, поэтому значения могут совпадать с кодами компилятора.

## Структуры и номинальные ID (0.3)

~~~text
type NodeId = distinct Int;
struct Node { id: NodeId, name: String, children: List<Node> }

fn main() -> Unit effects { state, io } {
    var node = Node(name: "root", id: NodeId(1), children: list_new<Node>());
    let previous = node;
    node.name = "updated";
    print(previous.name); // root: структура копируется по значению
    print(node.id.value); // 1: явное извлечение основы ID
}
~~~

Все поля конструктора обязательны, именованы и указываются один раз; порядок
может отличаться от объявления. Выражения вычисляются в порядке записи аргументов.
Поля читаются через точку; вложенное присваивание разрешено только если корень —
локальная переменная `var`. Присваивание полю временного значения запрещено.
Пустая структура допустима. Сравнения структур и match по структуре пока нет.

Distinct создаёт отдельный тип с основой Int, Float64, Bool или String. Разные ID нельзя
неявно смешивать, сравнивать или складывать. `NodeId(1)` оборачивает Int;
`id.value` извлекает Int. Равенство, print и to_string поддерживают одинаковые
distinct-типы. Другие операции требуют явного извлечения основы.

Прямые циклы полей структуры/enum запрещены. Циклы через коллекцию допустимы,
так как коллекция хранит handle конечного размера. Структура с полем List или
Dict копирует handle; содержимое коллекции остаётся общим.

## Обобщённые коллекции (0.3)

Типы: `List<T>` и `Dict<K,V>`, в том числе вложенные. Пользовательские
generic-функции, структуры и enum описаны в разделе 0.5.2 выше. Аргументы типов
конструкторов указываются явно; у остальных операций выводятся из аргументов.
Вывод по аннотации результата `let x: List<Int> = list_new();` не поддержан:
нужно `list_new<Int>()`.

Все операции ниже требуют `state`:

| Операция | Результат |
|---|---|
| `list_new<T>()` | Пустой List<T> |
| `list_len(items)` | Int |
| `list_get(items, index)` | Копия T |
| `list_set(items, index, value)` | Unit |
| `list_push(items, value)` | Unit |
| `list_truncate(items, length)` | Unit; длина только уменьшается |
| `dict_new<K,V>()` | Пустой Dict<K,V> |
| `dict_len(items)` | Int |
| `dict_has(items, key)` | Bool |
| `dict_get(items, key)` | Копия V; отсутствующий ключ — ошибка runtime 70 |
| `dict_get_or(items, key, fallback)` | Найденное V или fallback |
| `dict_set(items, key, value)` | Unit; вставка или замена |
| `dict_remove(items, key)` | Bool; был ли удалён ключ |

Ключи словаря — Int, Bool, String или distinct-обёртка такой основы.
Строковые ключи сравниваются по байтовому содержимому, включая NUL.
Произвольный тип V может содержать структуры, enum и коллекции.
Извлечение структуры даёт копию: для изменения элемента применяется list_set
или dict_set. Итераторов словаря и определённого порядка ключей пока нет.

Все аргументы вычисляются слева направо. В частности, fallback у dict_get_or
вычисляется даже при наличии ключа. Ошибки индекса списка завершают процесс с 70.
Старые IntList/StringList сохранены, но это отдельные типы без неявного преобразования
в List<Int>/List<String>. [Модель памяти](MEMORY.md).

## Строковое удобство (0.3)

`String + String` соединяет строки. `to_string` принимает Int, Float64, Bool, String и
distinct-обёртки. Преобразования в конкатенации явные:

~~~text
print("count=" + to_string(list_len(items)));
~~~

Числа форматируются десятично, Bool — как true/false. Эти операции чистые
и могут использоваться в контрактах. Пользовательского форматтера пока нет.

В 0.5 `f"count={list_len(items):d}"` форматирует выражение внутри строки.
Формат обязателен: `d` для Int, `s` для String, `b` для Bool, `display` для scalar
или distinct-обёртки. `{{` и `}}` дают буквальные скобки. Обычные escape-последовательности
сохранены. Разрешены вложенные строки, match и интерполяция; сырые переводы строки
и комментарии внутри литерала запрещены. Выражения вычисляются слева направо один
раз и сохраняют собственные эффекты. Форматирование само по себе чистое.
Форматтер сохраняет весь литерал, включая пробелы внутри выражений.
Полный контракт: [FORMATTING](contracts/FORMATTING.md).

## Дополнительные операции ОС для инструментов (0.3)

Полные сигнатуры и эффекты заданы в [общем каталоге](BUILTINS.md).

- `process_run_files(arguments: StringList, stdoutPath: String, stderrPath: String,
  timeoutMs: Int) -> Int` требует process, state, io. Файлы создаются/перезаписываются.
  Ноль отключает тайм-аут, диапазон 0..2147483647. Возвращает код ребёнка, 124 при
  тайм-ауте; ошибка запуска на Windows возвращает -1. Коды приложения могут совпасть
  с этими значениями. Два имени выходных файлов должны обозначать разные файлы.
- `make_dir(path) -> WriteResult` требует io; создаёт один уровень, принимает
  уже существующий каталог, но отвергает существующий обычный файл.
- `set_env(name, value) -> Unit` требует process; меняет окружение текущего
  процесса и будущих детей, не родительского терминала.
- `set_current_dir(path) -> WriteResult` требует io и process.
- `file_identity(path) -> StringResult` требует io: непрозрачная идентичность
  существующего файла, `Ok("")` для отсутствующего пути, `Err` при отказе ОС.
  Алиасы одного файла дают одинаковую идентичность; это не постоянный ID.
  [Контракт защиты исходников](contracts/DRIVER-SAFETY.md).
- `write_stdout(text) -> Unit` требует io: записывает точные байты без добавления
  перевода строки и сбрасывает буфер; ошибка вывода завершает процесс с кодом 70.
  В Windows использует двоичный режим на время вызова. Поведение `print` не меняется.

Вызовы процессов не проходят через shell. На Windows тайм-аут завершает job object
с дочерним деревом. POSIX-реализация пока не прошла платформенную проверку.
## Модули (доступны с 0.6)

`import "math.vela" as math;` открывает public API как `math::name`;
`import "math.vela";` открывает public имена без префикса. Импорты идут перед
объявлениями. Объявления private по умолчанию; `pub` разрешён для функций и типов.
Публичный API не может содержать private типы. Циклы импортов разрешены, циклы
типов по значению запрещены. Путь относителен импортирующему файлу. Собственные
имена имеют приоритет, неоднозначные open imports отклоняются при использовании.
Generic-тела разрешают имена в определяющем модуле. Пределы: 256 файлов,
глубина 128, 16 MiB нормализованного исходника. Полный [контракт](contracts/MODULES.md).
