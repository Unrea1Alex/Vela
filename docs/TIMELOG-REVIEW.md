# Прикладная проверка Vela: TimeLog

2026-11-04, Windows x64/MSVC. По отдельному поручению пользователя написано
[небольшое приложение](../apps/timelog/README.md) на существующей Vela 0.5.
Этап 0.6.1 остаётся следующим; новые конструкции языка не добавлялись.

## Результат

TimeLog читает UTF-8 TSV, проверяет строки, суммирует минуты по проектам и сохраняет
автономный HTML-отчёт. Демонстрационный журнал: 5 записей, 3 проекта, 290 минут;
Vela — 145, Spline — 110, Инструменты — 35. Готовый executable работает без
Vela, MSVC, Python, интернета и JavaScript. Исходник: [main.vela](../apps/timelog/main.vela).

В приложении используются generic-функция `with_context<T>`, `Result` и `?`,
match-выражения, структуры, List/Dict, диапазоны, snapshot-for и интерполяция.
Они дали ожидаемое поведение в проверенных сценариях. Ошибки входных данных
возвращаются как `AppError`, а не приводят к аварии; runtime-предусловие `duration`
не выдаётся за статическое доказательство. Процессная модель памяти не менялась.

## Найденная и исправленная ошибка

`fmt` оформлял возвращаемый `Result<T, E>` как `Result < T, E >`, если дальше
стояли `effects`, `requires` или `ensures`. Это нарушало контракт компактных
generic-скобок, хотя программа продолжала компилироваться. Ошибка обнаружилась
в четырёх функциях приложения.

В [formatter.vela](../selfhost/formatter.vela) исправлено распознавание этих
суффиксов; комментарий между типом и суффиксом пропускается при распознавании
и сохраняется в результате. Четыре регрессионных теста проверяют компактность
и повторное форматирование. До исправления целевой стенд дал 77 pass / 4 fail,
после — 81 pass / 0 fail. Набор включает прикладные и существующие fmt-проверки.

## Что я бы изменил дальше

1. **Стандартная работа с текстом и путями — 0.6, затем 0.7.1–0.7.2.**
   `split`, `trim`, `utf8_width`, `valid_text`, `html` и `parent_path` занимают
   заметную часть приложения. Это повторяемые алгоритмы, для которых нужны
   модули и библиотека с определёнными контрактами UTF-8/Bytes/Path.
   Различать проверку корректности UTF-8 и прикладной запрет управляющих символов.

2. **Единый тип результата нового I/O API — 0.7.2.**
   Для использования `?` сейчас приходится преобразовывать `StringResult` и
   `WriteResult` в `Result`, затем добавлять контекст ошибки. Сам `?` удобен;
   неудобство находится на границе старых builtin. Новые `std.fs` API должны
   возвращать единообразные типизированные ошибки; старые интерфейсы требуют
   явного плана совместимости. Нужны ограниченное чтение и общий помощник
   атомарной записи с определённым поведением очистки и отказов.

3. **Удобное формирование текста — кандидат для 0.7.2.**
   HTML/CSS приходится держать в длинном литерале с экранированием кавычек,
   а минуты дополнять нулём вручную. Проверить потребность в raw/многострочных
   литералах, шаблонах или ресурсах проекта; для чисел — в ширине и заполнении.
   Это предложение, не новый синтаксический контракт.

4. **Меньше шума сборки — оценить в 0.6.4.**
   MSVC сообщает C4102 для неиспользуемых сгенерированных меток циклов.
   Лучше не генерировать ненужные метки либо дать узкое обоснованное решение,
   сохранив видимость настоящих ошибок C-компилятора. Это не ошибка вычислений.

Эта программа подтверждает пригодность текущего языка для небольшой пакетной
утилиты. Она не проверяет GUI, сеть, длительную работу или другие платформы.
Ограничение 1 MiB применяется после чтения файла целиком, snapshot-for выделяет
дополнительную память, а процессная область освобождается при завершении.
Для долгоживущих приложений остаются задачи памяти/ресурсов следующих этапов.

## Версии и поставка

Исправление форматтера установлено в рабочий `bin/velac.exe` после verify.
Версия пока сообщает 0.5.0; это изменение рабочей базы после выпуска.
Архив `dist/vela-0.5.0-windows-x64.zip` не изменён и содержит прежние 626 проверок.
TimeLog поставлялся отдельным локальным архивом `dist/timelog-windows-x64.zip`
(архив не входит в Git; [инструкция сборки](../apps/timelog/README.md)).
Для следующей поставки компилятора требуется включить `apps/timelog/main.vela`,
который теперь использует общий тестовый стенд.
