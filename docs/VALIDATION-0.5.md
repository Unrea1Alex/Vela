## Восстановление, примеры и документация

Обновлённый `bootstrap/velac.c` самостоятельно собран MSVC, без Vela executable
как входного компилятора. Восстановленный compiler сообщил 0.5.0, проверил свой
исходник и собрал pipeline; вывод: `total=10`, `invalid input rejected`.
[Recovery evidence](stage05-recovery-evidence.json), логи `build/stage05/recovery/`.

Все восемь примеров пересобраны, фактический вывод сверен с независимыми ожиданиями.
[Манифест](../bin/build-manifest.json). Pipeline использует generic Batch, явное
преобразование IntResult, Result/?, диапазоны, snapshot-обход и интерполяцию.
Проверены локальные ссылки документации и точный Unicode span ошибки внутри
интерполяции: [свидетельство](stage05-documentation-evidence.json).

## Границы проверки

После выпуска выполнена [прикладная проверка TimeLog](TIMELOG-REVIEW.md).
Текущая рабочая база включает исправление fmt и 62 новые проверки: **688/688**,
failed=0, skipped=0; три поколения, C fixed point и bundler fixed point пройдены.
`bootstrap-evidence.json` и `test-evidence.json` отражают этот последний прогон;
`stage05-*.json`, `delivery-evidence.json` и архив Vela 0.5.0 описывают прежний релиз
с 626 проверками. Архив компилятора в рамках прикладной задачи не перевыпускался.
Свидетельства TimeLog: [timelog-evidence.json](timelog-evidence.json).

Linux/macOS/GCC/Clang не проверялись. PE-файлы не объявляются побайтно
воспроизводимыми: C fixed point не гарантирует одинаковых путей/метаданных PE.
Нет формального доказательства корректности и статического доказательства контрактов.
Generic-тела проверяются для используемых конкретных экземпляров; неиспользованные
тела только разобраны. Память остаётся процессной областью, snapshot for требует
O(n) дополнительного хранения. Нет модулей, GC, callable/closure, публичного FFI,
LSP и сетевого/GUI runtime. Следующий этап — 0.6.1 по roadmap.

Предыдущие измерения/свидетельства 0.4 сохранены в `docs/stage04-*.json`; они
описывают историческую базу, а не повторную проверку текущей версии.
